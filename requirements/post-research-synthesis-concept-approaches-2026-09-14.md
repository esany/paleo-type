## 2. Restatement of the empirical phenomenon

The current evidence does **not** support describing the whole problem as one missing `Research Framing` function.

A central scientific asymmetry is nevertheless visible:

> The repository became strong at executing, evidencing, assuring, persisting and restarting an already-selected bounded task, while the formation and comparative testing of several serious next research questions from a rich state was less operationally demonstrated.

That asymmetry matters because a system can execute a selected task correctly while the selected question is too small, uses the wrong analytical scale, follows the most addressable residual, or is attractive because an Issue/artifact/support step is easy to act on.

The authoritative scholarly workflow already requires movement from research goal to research question, evidence need, disciplinary method, claim type and permitted conclusion. The Research therefore does not automatically establish a missing normative layer; it establishes a need to inspect whether existing semantics are sufficient and where their operational efficacy fails.

At the same time, other mechanisms remain analytically distinct:

- #165: a valid evidence/correspondence relation can be promoted into stronger Source-/analysis-unit authority;
- #169: a correct resource/readiness fact can gain invalid task/roadmap authority;
- #162: a visible derived/planning surface can become stale relative to canonical state;
- #90: an already-desired normative/technical control can remain unenforced.

#184/#186 therefore reject both `every problem = missing Requirement` and `every problem = activation gap` as master explanations.

#191 changes one important absence-of-demonstration result: plural serious next-question formation is now positively demonstrated across three heterogeneous fixtures. What recurs is thin and adaptive rather than one universal algorithm: consequence-sensitive relation finding, question-dependent scale/context adjustment, discriminating-evidence identification, source-critical reformulation, explicit evidence ceilings and preservation of alternative directions until purpose/priority authority selects among them.

Still **not demonstrated** are a universal Framing algorithm, one Candidate-Question schema, one scoring model, one fixed competence topology, one preferred AI allocation or one control-plane architecture.

## 3. Governing concept: a bounded Capability / Requirement Synthesis Admission

The next epistemic move should be a **bounded post-Research synthesis / Requirements disposition pass**, not another broad Research programme and not a System Change Plan.

The pass asks what the evidence justifies before assuming any material change is necessary.

Preferred reasoning direction:

```text
Research finding
→ existing canonical owner / Requirement
→ observed scholarly / epistemic need
→ concrete mechanism / efficacy status
→ normative consequence
→ possible capability implication
→ only then: whether any material Concept step is warranted
```

Forbidden shortcut:

```text
problem
→ new Capability label
→ schema / workflow / agent / architecture
```

The synthesis may legitimately end with **no material system change**.

## 4. Concept approach A — Evidence-to-Disposition Synthesis

### Hypothesis

The smallest useful synthesis is not a new framework but a one-time evidence disposition that traces each decision-relevant Research finding against current canonical owners and existing Requirements.

### Required meaning

For each material finding, reconstruct:

```text
Research finding
→ evidence / fixture
→ existing METHOD / Requirement owner
→ scholarly / epistemic need
→ observed failure / efficacy mechanism
→ normative disposition
→ possible capability implication, if any
→ remaining specialist / Human Owner / validation dependency
```

This is traceability for the synthesis, not a mandatory durable schema.

### Legitimate terminal dispositions

The pass must permit asymmetric outcomes, including:

- `no change required`;
- `existing Requirement adequate`;
- `Requirement adequate; mechanism/timing/propagation/enforcement inadequate`;
- bounded technical enforcement issue;
- several independent needs with no single solution justified;
- genuine new Requirement candidate;
- possible generic capability need, still pre-normative;
- irreducible specialist judgement;
- irreducible Human-Owner judgement;
- evidence insufficient for promotion;
- Project-/source-specific rather than generic.

A process that cannot honestly return `no change` is already solution-biased.

## 5. Concept approach B — Requirement efficacy must remain mechanism-specific

`Requirement existence != Requirement efficacy`, but efficacy is not itself one failure mechanism.

The synthesis should therefore avoid the catch-all term `activation gap` unless the evidence genuinely supports that narrower diagnosis.

Candidate diagnostic distinctions, used only when evidenced, include:

- normative Requirement actually missing;
- existing Requirement semantically sufficient;
- semantic/authority translation failure;
- timing/sequence failure;
- mechanism missing despite sufficient normativity;
- visibility/freshness/propagation failure;
- deterministic enforcement absent;
- review/assurance not reaching the relevant premise;
- source-/Project-specific problem;
- no system gap.

These are analytical distinctions, not a new controlled taxonomy to institutionalize by default.

## 6. Concept approach C — thin adaptive scholarly operations, not a preselected Capability block

#191 gives positive evidence that several scholarly operations recur across heterogeneous fixtures. The synthesis should examine whether those recurrences have generic system significance without deciding their representation in advance.

Observed recurring operations include:

1. produce several plausible scientific directions rather than following one addressable residual;
2. derive stronger questions from consequential relations/patterns, not merely unresolved detail;
3. let question/claim/evidence determine when analysis scale and context widen or narrow;
4. identify evidence that could discriminate or materially advance a question;
5. state source-critical/evidential limits and legitimate terminal outcomes;
6. allow source-type/domain expertise to reformulate the question itself;
7. preserve multiple credible directions without converting them into task authority.

Open synthesis question:

> Are these best understood as one new generic Capability, several already-existing METHOD functions, an efficacy/activation problem, review practice, or simply constraints on good scholarship that need no additional system representation?

The term `Capability need` is therefore strictly **pre-normative** here. It must not imply a component, role, stage, schema, API or owner.

## 8. Concept approach E — preserve authority and judgement separation

The synthesis must keep at least three decision classes distinct:

### Qualified specialist judgement

Owns contested disciplinary/domain judgement where the consequence or uncertainty warrants specialist review. AI-assisted research is not independent specialist validation.

### Human Owner judgement

Owns purpose, material priority/scope, material research-system admission and other governance-reserved decisions. Generated questions are proposals, not task authority.

### Deterministic system enforcement

Appropriate only for already-settled semantics and machine-checkable invariants. Technical `PASS` does not create scholarly acceptance.

A useful synthesis question is therefore not `what remains human?` but:

```text
What remains specialist/domain judgement?
What remains Human-Owner purpose/priority/admission?
What can be deterministically enforced because semantics are settled?
What needs no new system mechanism at all?
```

## 9. Concept approach F — the Disposition Package must not become meta-machinery

The one-time synthesis artifact may use tables/matrices as working analysis aids, but it must not silently become a durable Capability Registry, Requirement State System, workflow engine, routing topology or second truth store.

Whether any structure from the synthesis deserves durable canonical representation is itself a later conclusion requiring evidence and the normal D-016 path.

This protects against a recurrent correction-overcorrection pattern:

```text
real problem
→ useful corrective abstraction
→ abstraction becomes new default machinery
→ machinery creates its own authority / overhead / blind spots
```

The goal is to make the system more reliable, not merely larger.

## 10. Concept approach G — smallest adequate response, including no change

If a real generic gap survives disposition, the next question is not immediately `what architecture?` but:

> What is the smallest property or mechanism that must change to remove the demonstrated failure while preserving productive scholarly flexibility?

Possible responses include, in increasing order of materiality:

- no change;
- clarification of an existing owner;
- repair of a stale/derived surface;
- stronger use/review of an existing boundary;
- bounded deterministic enforcement of settled semantics;
- refinement of an existing Requirement;
- genuinely new Requirement;
- only then a separate Concept step comparing solution forms.

No assumption is made that exactly one change must emerge. Several independent problems may remain independent.

## 11. Local anti-regression questions for the bounded synthesis pass

The repository already has general safeguards in `AGENTS.md`, `methodology/quality-and-learning.md`, `methodology/workflow.md` and `methodology/maintenance.md`. The following questions are **local acceptance criteria for this transition only**, not a new gate system.

1. **Evidence-first** — Can every disposition be traced to a concrete frozen finding from #184/#185/#186/#191, or is its form really inherited from the old Concept Candidate?
2. **Existing-owner-first** — Which current METHOD/Requirement owner already governs the need? Is semantics missing, or only efficacy in one mechanism?
3. **No master-cause compression** — Have translation, timing, mechanism, freshness/propagation, enforcement and true normative gaps remained distinct, or were they recompressed into `Activation`/`Framing`?
4. **No capability laundering** — Is `Capability` merely a provisional name for an evidenced recurring need, or has it silently become a component, role, stage, schema or API?
5. **Negative outcome allowed** — Could the analysis honestly end with `no change`, `existing Requirement sufficient`, `specialist judgement`, `Human Owner judgement`, `Project/source-specific` or `insufficient evidence`?
6. **Adaptive scholarship preserved** — Would a proposed norm still allow question-/claim-/source-/purpose-dependent scale, context and competence interaction, or has it frozen an adaptive practice into one sequence?
7. **Authority preserved** — Did specialist judgement, Human-Owner authority and deterministic settled semantics remain distinct when translated into system language?
8. **Addressability-bias check** — Is a proposed mechanism scientifically required, or merely attractive because schema, Issue, workflow, software or AI makes it easy to represent?
9. **Smallest adequate response** — Would clarification, review practice, propagation repair or bounded enforcement solve the demonstrated failure before new normativity is introduced?
10. **Meta-machinery check** — Is the disposition matrix still an analysis aid, or is it already being treated as a durable registry/state model/workflow?
11. **Generic-Fit** — What evidence supports generic promotion? A single case can falsify a bad generic assumption without defining its replacement architecture.
12. **Scope/priority check** — Did any synthesis result accidentally create a scholarly `NEXT ACTION`, Project priority or implementation authority? If yes, an authority boundary was crossed.

## 12. Three hard stop rules

### Stop 1 — no evidence + owner + gap, no normative promotion

If a proposed normative consequence cannot name:

1. the concrete Research finding/evidence;
2. the applicable canonical owner;
3. the specific unresolved gap;

then do **not** promote it into a Requirement or Capability conclusion.

### Stop 2 — if a solution object is needed to explain the need, return to the need

If the synthesis must invent a schema, role, stage, workflow, API, agent topology or architecture in order to make the supposed need intelligible, return to the lower-level scholarly/system property and restate it without the solution object.

### Stop 3 — sufficient existing normativity must not be duplicated

If an existing Requirement/METHOD owner already carries the necessary semantics, do not add a second norm merely for visibility, reassurance or local convenience. Diagnose the concrete efficacy/translation/enforcement problem instead.

## 15. Exit questions

The bounded pass is complete when it can answer, with evidence and canonical-owner traceability:

- What must be preserved?
- What is already adequately normative?
- What fails operationally despite adequate normativity, and by which mechanism?
- Where is there a genuine normative or reusable-system need?
- Which recurring #191 operations are system-relevant, if any, and at what abstraction level?
- What must remain specialist judgement?
- What must remain Human-Owner judgement?
- What can be deterministically enforced because semantics are settled?
- Is any material research-system change justified at all?

Then stop.

If a material change is justified, it enters a **separate Concept stage** under `methodology/maintenance.md`. This file does not itself admit that stage or any implementation.
