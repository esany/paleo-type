Gap type is not absence of scholarly process/maturity semantics.

### C. Execution/restart mechanics — STRONG BUT TASK-BOUND

`workflow.md` already requires reconstructable role/task/stage/cursor/prerequisite/evidence/completion/return meanings and contains strong local repair, no-progress, Domain↔Dev, dependency and freshness controls.

Current evidence suggests the execution contract is strongest **once a bounded task/current target already exists**.

### D. Canonical ownership / deterministic support — STRONG IN STRUCTURE/CONTROL PLANE

Existing Source/File/Project-use contracts, validators, intake/context tooling and failure-derived regression tests provide substantial deterministic support for identity, provenance, references, routing boundaries and restart surfaces.

The missing integration must reuse these rather than replace them.

### E. Quality review — COVERED AS DIMENSIONS, NOT YET A COMPOSED OUTCOME RESOLVER

`quality-and-learning.md` already separates technical assurance, scholarly adequacy, specialist validation, Human/governance review and restartability, and includes Goal Alignment.

It does not by itself resolve which unmet scholarly/system requirement should be executed next to reach a stated outcome.

### F. Initial principal gap hypothesis — COMPOSITION / DERIVATION

The strongest current hypothesis remains that the repository has many mature semantic owners but lacks an operational composition layer that can reliably derive:

```text
owner-authorized desired outcome
+ canonical purpose/scope
+ current evidence/maturity
→ unmet requirements
→ required capabilities / execution mode
→ bounded vertical work
→ validated result / legitimate ceiling
```

without relying on the current AI to reconstruct the chain from distributed prose.

This remains a hypothesis to be tested against all existing requirements/owners before Phase 1 calls any semantic genuinely missing.
