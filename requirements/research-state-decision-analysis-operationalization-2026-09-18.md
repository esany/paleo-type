## 3. Finding: the scientific semantics already exist

The repository already contains the substantive method.

### 3.1 Research-question control already owns direction formation

`methodology/historical-source-workflow.md` already states:

- material research serves an explicit question or required source-representation task;
- the reasoning chain is research goal → research question → evidence → disciplinary method → claim → permitted conclusion;
- when a material next-direction decision is needed and no owner-selected next scholarly scope/question is in force, the system must **not infer priority from unresolved, available or easy work**;
- it must form and scholarly challenge multiple evidence-grounded candidate directions where the evidence supports them;
- each serious candidate must expose scholarly consequence, discriminating/advancing evidence, evidence ceiling, question-dependent analytical scale/context and materially relevant disciplinary perspective;
- candidate directions are proposals only and do not create scope, priority or a next action;
- no fixed number, scoring/ranking, candidate object, competence topology or new framing layer is prescribed.

This is already the core scientific rule requested by the Human Owner.

### 3.2 The end-to-end scholarly method already supplies the research pipeline

The same file already owns the iterative scholarly activities:
- source group and provenance;
- documentary/material structure;
- diplomatic representation;
- palaeographic/philological analysis;
- independent comparison/collation;
- normalization/identification/enrichment;
- historical source criticism/interpretation;
- critical consolidation/validation;
- edition/publication.

It also states that these activities and the scholarly maturity gates are complementary, not a rigid waterfall, and that later findings may reopen earlier work.

Therefore **no new phase model is required**.

### 3.3 Dynamic transdisciplinarity already exists

The method already requires source-/question-relative activation of:
- archival science/diplomatics;
- palaeography;
- historical philology/language history;
- scholarly editing/textual criticism;
- historical source criticism;
- codicology/material study when relevant;
- onomastics/toponymy when relevant;
- metrology/numismatics/accounting when relevant;
- legal/ecclesiastical/administrative/economic/social or other domain history when the claim requires it;
- research-data/software/AI/HITL support subordinated to scholarship.

Leadership is claim/question-relative, not a permanent discipline hierarchy.

Therefore **no discipline registry or fixed sequence is required**.

### 3.4 Quality criteria already exist

`methodology/quality-and-learning.md` already owns:
- evidence adequacy;
- separation of observation, reading, normalization, identification and interpretation;
- genuine independence of corroboration;
- persistence in canonical owners;
- alignment with the authorized research goal;
- technical assurance;
- scholarly adequacy;
- specialist validation as distinct from AI/method compliance;
- restartability/challengeability;
- adversarial attempts to falsify important claims.

The full `requirements/domain-requirements.tsv` supplies the domain-specific quality detail.

Therefore **no new quality-score system is required**.

### 3.5 Project authority already protects the Human decision

`methodology/project-lifecycle.md` and Project state already own:
- Project purpose;
- current scope;
- current work target;
- absence of a current target;
- the rule that Source/File availability, research function, historical work or gate state do not create priority.

Therefore a research-state decision analysis must **prepare** the decision and may never write a new Project priority by itself.

### 3.6 Scholarly maturity gates remain evidence claims only

`methodology/research-gates.md` already owns scope-bound maturity semantics.

The gates are inputs to the analysis:
- they show what has been established for a stated scope;
- they reveal unmet scholarly requirements;
- they may be reopened.

They are **not the decision algorithm**.

## 4. Exact operational gap

The gap is narrower than a new maturity mechanism.

Current owners answer the pieces separately, but normal execution does not yet guarantee this transition:

```text
completed / paused / bounded scholarly work
        +
current Project purpose
        +
current evidence and scope-bound maturity
        +
residual uncertainty / evidence ceilings
        +
question-relative disciplinary requirements
        +
quality / specialist / technical assurance state
        ↓
TRANSDISCIPLINARY ITERATION-BOUNDARY DECISION ANALYSIS
        ↓
human-readable candidate research directions
with reasons, expected scholarly consequence, evidence path,
disciplinary requirements, uncertainty/ceiling and relevant costs/constraints
        ↓
Human Owner selects / reframes / declines a new research direction
        ↓
only then: Project scope / current work target changes
```

The missing operational properties are:

1. **trigger** — when this analysis must happen;
2. **composition** — which existing scholarly/quality inputs must be brought together;
3. **decision-surface meaning** — what the Human Owner must be able to understand;
4. **return boundary** — candidate directions remain proposals until owner selection.

## 5. Minimum normative propagation

### 5.1 Primary scholarly owner: `methodology/historical-source-workflow.md`

This is the correct semantic owner.

The existing “pre-priority research-direction formation” rule should be **expanded/clarified**, not replaced.

Minimum addition:

#### Iteration-boundary research-state decision analysis

When:
- an owner-authorized scholarly scope/question has reached a substantive terminal point, evidence ceiling or deliberate pause; **and**
- a material decision about continuation/reframing/new direction is actually needed; **and**
- no owner-selected next scholarly direction is already in force;

then perform one integrated source-critical decision analysis before asking the Human Owner to choose a new priority.

The analysis must use, as applicable:

- the governing research purpose and question;
- the actual scholarly result achieved, not task completion;
- exact evidence basis and current evidence limits;
- scope-bound maturity state;
- unresolved questions classified by their consequence for the research goal;
- whether current findings confirm, weaken, refine, enlarge or invalidate the working research question;
- all materially relevant disciplinary perspectives, activated dynamically from the question/source/claim;
- whether further work in each candidate direction is likely to discriminate a real scholarly question or merely accumulate detail;
- evidence required to advance/falsify each serious candidate;
- likely evidence ceiling and specialist dependency;
- the state of technical/research infrastructure **only insofar as it affects reliable execution/auditability**, never as a substitute for scholarly value;
- the expected kind of usable scholarly result.

The Human-facing output must make clear:
- what is known and why;
- what remains unknown and why it matters or does not matter;
- what materially different research directions are supported;
- what each direction could add to knowledge;
- what evidence/method/disciplinary competence each direction needs;
- what could falsify or terminate each direction;
- which decision is genuinely reserved to the Human Owner.

Do not rank mechanically, score numerically or create scope automatically.

This is **not a new stage**. It is the application of existing research-question control at a real iterative decision boundary.

### 5.2 Operational trigger owner: `methodology/workflow.md`

The workflow should not own the scholarly content above.

It should add only the execution trigger/return rule:

At a substantive research-workblock terminal state:
- if an authorized higher-level research cursor still exists, return to it;
- if the current bounded scholarly question has ended/paused and a material new-direction decision is needed, invoke the research-state decision analysis owned by `historical-source-workflow.md`;
- if no direction decision is needed, do not generate candidate work;
- candidate directions returned from the analysis do not become executable work until owner authority exists.

This belongs near:
- research-workblock terminal semantics;
- result handoff / return question;
- current-work-target authority.

### 5.3 Quality owner: `methodology/quality-and-learning.md`

Add a **decision-analysis quality check**, not a new maturity scale.

A valid research-direction decision surface must pass:

1. **Goal relevance** — every candidate is tied to the Project's scholarly purpose, not available/easy work.
2. **Evidence discrimination** — candidate value is grounded in evidence that could actually advance or falsify the question.
3. **Question reappraisal** — the current question itself is tested, not assumed permanent.
4. **Transdisciplinary adequacy** — all materially relevant disciplines are considered; irrelevant disciplines are not activated ritualistically.
5. **Epistemic separation** — source observation, reading, identification, interpretation and contextual knowledge remain distinct.
6. **Uncertainty significance** — unresolved items are classified by consequence; “unresolved” alone does not create a programme.
7. **Independent challenge** — serious candidate claims/directions receive adversarial or independent checking proportional to consequence.
8. **Specialist boundary** — specialist judgement is visible where it matters.
9. **Technical subsidiarity** — technical readiness/complexity affects feasibility and auditability, not scholarly priority by itself.
10. **Human comprehensibility** — a non-specialist owner can understand why the alternatives differ and what decision is actually being requested.
11. **No hidden ranking** — wording does not smuggle an AI preference into a supposedly neutral option set.
12. **Restartability** — the decision basis can be reconstructed from repository state/evidence, not only from the originating chat.

### 5.4 System integration owner: #225

#225 should record that this iteration-boundary decision analysis is the **human decision surface required when the outcome-control context reaches a legitimate “new owner direction required” state**.

This does not create a second research method.

It closes a specific usability/composition gap:

> “Human authority required” is not a sufficient user-facing terminal output when the repository already contains enough scholarly evidence to prepare a transdisciplinary decision basis.

The system should first prepare the decision basis described above, then ask only the genuine purpose/priority choice.

## 8. Falsification fixtures

The propagation is acceptable only if it survives all of these.

### Reg. Ii 3

The decision analysis must not call File/crosswalk preparation scientific maturity.

It should recognize that the current research-direction question is substantially one of **research framing** and derive serious evidence-grounded candidate questions only if a direction decision is actually being requested.

### Reg. Ii 4

The decision analysis must not infer “critical consolidation next” merely because the existing bounded Knau scope has reached controlled comparison.

It must consider materially different possibilities:
- consolidation of the existing result;
- specialist follow-up only if a residual is consequential;
- a new question/scope;
- deliberate no further work.

The relative scholarly value must come from purpose/evidence, not gate order.

### Reg. Ii 5

The decision analysis must respect the bounded evidence ceilings already established.

Unresolved signs/words must not generate work merely because they are unresolved.

It must ask whether resolving them would materially affect the intended historical/editorial result.

### Generic failure test

If the decision surface can be produced by merely reading the highest reached gate and listing the next gate, it fails.

If it can be produced without asking which disciplines are relevant to the actual question, it fails.

If it reads like a status summary rather than explaining consequential alternatives, it fails.
