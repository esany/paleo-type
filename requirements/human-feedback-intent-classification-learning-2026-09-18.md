## 1. Concrete failure

During the 2026-09-18 maturity/transparency discussion, Human corrections about shallow, confusing, repo-detached or misframed output were repeatedly interpreted as if they directly selected a new product/research-system direction.

Observed failure chain:

Human dissatisfaction / correction → assistant infers a new problem definition → new framing/mechanism is designed → local response becomes a new work branch → prior repo-backed systemic result loses dominance → Human has to correct the drift again.

Concrete examples included:
- replacing a repository-audited multidimensional maturity concept with shorthand status summaries;
- then replacing the shorthand with simpler prose;
- then interpreting dissatisfaction with the representation as a need for a research-question / research-direction mechanism;
- then treating correction of that drift as a new maturity/progress design branch;
- later repository cleanup was required to restore the prior higher-level #225 cursor.

The material defect was **Human-intent misclassification**, not absence of a scholarly method.

## 2. Human clarification

A Human statement, request, complaint or correction is an expression of a need. It may represent a direct desired product/research change, but it may also identify an undesirable symptom caused by AI/system behavior. These meanings must not be silently collapsed.

When more than one materially different interpretation remains plausible, and choosing one would materially redirect work, change scope/priority, promote a new requirement or create a new branch, ask the Human to clarify the intended decision before acting on that interpretation.

This is not a general clarification-first rule. Routine, reversible and repository-derivable work remains autonomous.

## 3. Interpretation discipline

A Human utterance is first evidence about need, dissatisfaction, constraint, desired outcome or decision intent. It is not automatically:
- a canonical Requirement;
- implementation admission;
- Project scope authority;
- a selected solution;
- a new programme branch;
- evidence that the governing objective is wrong.

A useful analysis distinction — not a canonical enum — is:
1. direct outcome/change request;
2. constraint or quality expectation;
3. symptom/failure feedback;
4. question/exploration;
5. explicit material authorization/decision.

One utterance may contain more than one of these meanings.

Before a Human intervention causes a material redirection:
1. re-resolve the current repository-backed objective/cursor;
2. reconstruct the underlying need and distinguish product change from execution/symptom feedback;
3. choose the narrowest valid disposition;
4. if material intent remains ambiguous, ask one focused clarification;
5. after local symptom correction, return to the prior valid cursor unless the Human actually changed purpose, priority or scope.

## 6. Generic learning

> **Human feedback must be interpreted first as evidence of need/constraint/symptom/outcome, not automatically as change authority or solution selection. A material reinterpretation of governing work requires clear Human intent or a clarification decision. Symptom correction returns to the prior valid cursor unless the Human actually changes purpose, priority or scope.**

## 7. Candidate regression — not yet promoted

Given a valid current cursor and Human feedback that an output is too shallow/confusing/technically framed, with two plausible responses — improve execution inside the current need or create a new system mechanism — the system must not silently choose the new mechanism. Preserve the current objective; treat the feedback as need/failure evidence; ask one focused clarification only if the material intent remains ambiguous; then return from local correction to the valid prior cursor.

Promote this to an executable regression only if the expected invariant can be tested without pretending that free-text intent classification itself is fully deterministic.
