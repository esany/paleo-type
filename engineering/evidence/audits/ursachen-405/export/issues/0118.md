## Purpose

Repair a planning-semantics drift found during the fresh Issue/backlog audit.

`MILESTONES.md` currently states that an open Issue without a Milestone is necessarily unscheduled/backlog. Fresh repository history disproves that as a universal rule: the completed Reg. Ii 4 research sequence (#96/#97 and successors) was actively driven from canonical Project state without Milestone assignment, and current #115 is likewise explicitly owner-selected/current in Reg. Ii 5 `STATUS.md` while unmilestoned.

## Change

- keep Milestones as optional human-readable target/phase groupings;
- make Project `project.yml` / `STATUS.md` and explicit owner selection authoritative for current scholarly priority;
- distinguish:
  - open + Milestone = grouped work;
  - open unmilestoned + canonical current owner = active ungrouped work;
  - open unmilestoned + explicit trigger = deferred backlog;
  - otherwise = ungrouped backlog requiring triage;
- do not create Milestones merely to prove that one already-clear current Issue is active;
- preserve G1–G6 and GOV milestone families as optional planning/navigation groupings.

## Non-changes

- no Project scope/gate/research truth changes;
- no Issue priority is selected by this PR;
- no new milestone is created;
- no METHOD/CORPUS model change;
- no workflow engine or new planning layer.

This is a bounded correction of GitHub planning semantics to match canonical ownership and observed repository practice.
