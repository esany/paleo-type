## Terminology / design correction — “minimal” must not become the governing threshold

Fresh check against current GO/AGENTS/workflow/maintenance/research-gates plus historical #208/#225 and current #307/#297 shows that the word **minimal** in the earlier #309 recovery/systemic wording is unsafe if read as “capture as little as possible” or “require the smallest prerequisite set”.

### Correct precedence

The repository's technical-subsidiarity rule is:

> use the **least complex representation/mechanism that still preserves all required scholarly distinctions, provenance, reproducibility, Human control, usability and restartability**.

Therefore the order is:

~~~text
scholarly / evidential / authority requirement
→ all materially necessary information and transition consequences
→ adequate / lossless / restartable state
→ only then choose the least-complex representation or mechanism
~~~

Not:

~~~text
start from a minimal state/mechanism
→ hope that enough scholarly meaning survives
~~~

### Why this matters here

Known repository evidence already warns against exactly this compression bias:

- #208 records **lean-down / function-loss risk** and specifically notes that simplification had stronger checks for data/state loss than for loss of cognitive/review functions;
- #225 treats quality attributes as **simultaneous, not tradeable by default** and defines lean delivery only as the smallest mechanism that preserves required quality;
- #307 demonstrates that compression/synthesis can erase derivational provenance and unresolved state;
- #297 shows that locally correct / bounded handling can still fail affected-network reconciliation;
- #309 itself demonstrates omission/materialization loss: safeguards against wrong mutation did not ensure that required state was actually present.

### Corrected threshold concept

For source-entry and later research work, use **activity-relative sufficiency and transition completeness**, not minimality.

Before a scholarly activity begins, all prerequisites whose absence could materially compromise:
- evidence identity / provenance,
- authority,
- claim validity,
- restartability,
- canonical ownership,
- downstream dependency,
- or required specialist/Human control

must be resolved or explicitly represented as an allowed unresolved condition for that activity.

When a result becomes consequential for later work, persist the **complete materially relevant state**, including uncertainty, negative/unresolved findings, provenance and affected-owner consequences. Do not save only the smallest local fact if that would force a later context to reconstruct meaning from Issue chronology/chat.

### What may still legitimately be “least complex”

Only the **implementation/representation choice after information requirements are complete** may be optimized for leanness.

Examples:
- choose one table rather than three if one table carries the full required meaning losslessly;
- avoid a workflow engine if a bounded preflight/validator suffices;
- avoid duplicate state if an existing canonical owner can carry the full requirement.

But:
- do not reduce the required information because a smaller schema is easier;
- do not reduce prerequisite coverage because a smaller preflight is easier;
- do not reduce propagation because only the local owner changed.

### Wording correction for #309

Read earlier phrases such as “minimal Project contract”, “minimum missing state” or “smallest safeguard” only in the sense of **least-complex adequate implementation after complete semantic requirements are established**.

For the current analysis the safer governing formulation is:

> **Before dependent research proceeds, establish a sufficiently complete, provenance-preserving, authority-correct and restartable canonical state for that activity; then implement that requirement with the least complex mechanism that is demonstrably lossless.**

No METHOD/schema/Project/Source state is changed by this correction.
