## Findings

### 1. Process/governance overhead is growing markedly faster than scholarly output — High
≈4,900 lines of methodology/governance/self-audit prose against 198 edited physical lines, produced in 93 commits over 6 days (49 on a single day) and well over 100 issues/PRs. A dedicated document family (`requirements/ai-role-handoff-engineering-analysis.md`, `…-control-audit.md`) analyses the AI role/handoff architecture that itself produced that analysis. The repository's own principles name this exact risk (D-008 "Automation must solve an observed bottleneck"; the Lean Test in `ai-governance.md`; L020 in `projects/ega-reg-ii-5-knau/LEARNINGS.md`) — they are followed on the research/transcription layer but not yet on the process layer.

### 2. Bus factor of 1, no documented independent specialist review yet — High
All 93 commits come from a single GitHub account. There is no second human contributor, and — despite an explicitly defined escalation path (`methodology/ai-governance.md` §4, "independent qualified human review") — no documented instance where an outside specialist was actually consulted. The repository correctly refuses to equate method-compliant AI work with expert validation in principle; that distinction remains untested in practice. Independent specialist access is not assumed to be available to the owner (see discussion below).

### 3. Five revisions of the Project-ownership model in six days — Medium
D-011 → D-012 → D-014/D-017 → D-018 trace five successive definitions of what a "Project" is; D-017 itself carries the status "under authority audit". Each revision is cleanly documented and traceable (a real strength), but the churn rate suggests a core model that could have stabilized earlier at this scale. The legacy directory `ega-reg-ii-5-knau` remains a standing path debt that has to be re-explained in every `STATUS.md`.

### 4. Test coverage secures only the deterministic layer — Medium
59/59 green, CI green — but every check concerns referential integrity, SHA-256 format, `part_of` acyclicity and structure, never the palaeographic or historical claim itself. The repository's own model treats this as correct by design (`"A technical PASS never establishes scholarly truth"`), but a green badge is easy for an outside reader to over-read as content validation.

### 5. High entry barrier for a new working context — Medium
`AGENTS.md` requires reading `GOVERNING_OBJECTIVE.md`, `AGENTS.md` and every applicable methodology file before any action — realistically several thousand lines before a single transcription line can be touched. Workable for the current single-owner setup; a steep cost curve against the repository's own stated "replaceable work-context" ambition.

### 6. Rights, provenance and restartability handling — Strength
No protected binary ever committed; controlled `storage_status` vocabulary with SHA-256 verification for `repo-preserved` entries; clean separation of identifiability, reproducibility and actual target-context accessibility (`LEARNINGS.md` L017/L018). The three `STATUS.md` files are, verified by direct reading, actually sufficient to reconstruct current work state without chat history — the restartability claim holds up under an independent read.

## Recommendations (priority order)

1. **Freeze new process artifacts.** No new methodology/role/audit files unless a concrete, repeated failure demonstrates the need — apply D-008 to the process layer itself, not only to tooling.
2. **Seek a low-barrier reality check instead of a formal expert engagement**, since the owner has no existing specialist access: post a narrowly scoped, cropped-image question to a palaeography-literate community (e.g. Geschichtsforum.de's Frühe-Neuzeit/Paläographie threads, AG Historische Grundwissenschaften) for one already-G4-complete locus, and record the outcome — positive or negative — in `LEARNINGS.md`.
3. **Lower the onboarding path.** Add a short pointer (10–15 lines) for the common case "work the next transcription line" that references the full methodology instead of requiring it front-to-back for routine work.
4. **Resolve the `ega-reg-ii-5-knau` legacy path** through the already-announced loss-checked rename instead of re-explaining it in every STATUS.md.
5. **Add a lint/type-check step to CI** (e.g. `ruff`, no extra dependency) as a cheap additional safety layer on the otherwise clean stdlib-only Python base.

## Scope and limits

This is a structure/process/code review, not a palaeographic, codicological or historical assessment of the readings at fol. 61v–63r or fol. 306v–309r. All figures were derived from the local checkout and the GitHub API on 2026-09-09 and are approximations, not certified metrics.

The broader recommendation above (#2) stands on independent grounds (bus factor / no documented outside check), not on that retracted argument.

**Reviewer provenance:** ChatGPT / GPT-5.6 Sol, owner-requested fresh repository review and correction after re-reading the current competence/requirements architecture.

### Correction to the previous diagnosis

The earlier framing that `paleo-type` still lacked a sufficiently developed domain-competence layer was too coarse.

Fresh review of `GOVERNING_OBJECTIVE.md`, the authoritative historical-source workflow, `requirements/domain-requirements.tsv`, source/context synthesis, quality/learning surfaces and current Project learnings shows that the repository already has a broad transdisciplinary competence model. It explicitly routes among archival science/diplomatics, palaeography/scribal evidence, historical philology/language history/lexicography, scholarly editing/textual criticism, historical source criticism, source-type/domain history, codicology/material studies, onomastics/toponymy, historical metrology/accounting/notation, research-data stewardship, research software/data engineering, AI/HITL, and human research usability/epistemic transparency.

The Governing Objective already requires the concrete source/problem to determine which disciplines, methods and expertise are jointly activated, and treats disciplinary practice, empirical evidence and experiential specialist knowledge as part of the relevant competence basis.

The Requirements layer also already captures the key distinction discussed in the recent audit:

- `REQ-PAL-004`: palaeographic comparison should record **discriminating graphical features**, not merely repeated words/silhouettes;
- `REQ-PHIL-005`: consequential lexical/semantic claims should cite the **actually inspected** dictionary/corpus/article entry or passage; current support is marked as a gap;
- `REQ-PHIL-006`: lexical plausibility may rank/test only graphically viable candidates after manuscript localization;
- `REQ-DOM-009`: **tacit expertise should generate explicit questions/candidates/tests rather than invisible conclusions**;
- related domain requirements keep manuscript wording, historical concepts, interpretation and validation distinct and expose specialist-review triggers where consequence warrants it.

Therefore the primary gap is **not competence routing** and not lack of another domain map.

### Revised three-layer diagnosis

1. **Competence routing — comparatively strong.**
   The repository already knows which disciplinary perspectives may become relevant and contains explicit epistemic/authority boundaries for them.

2. **Knowledge access / expertise activation — current likely bottleneck.**
   When a domain is triggered, the system does not yet consistently have fast, traceable access to the relevant specialist knowledge: diagnostic historical-script examples, historical spelling/morphology/semantics, archival/diplomatic parallels, source-type formulas, administrative/institutional context, regional terminology, names/places, accounting/metrological notation, comparable editions, current specialist literature, etc.

3. **Evidence adjudication — comparatively strong.**
   Existing Target-first, candidate separation, comparator discipline, Target Return, uncertainty preservation and canonical-owner rules substantially reduce the risk that plausible external knowledge becomes manuscript evidence by suggestion alone.

The present asymmetry is therefore:

> `competence can be routed` + `evidence can be adjudicated` **but** `relevant expertise cannot always be activated quickly and reproducibly`.

This can make a methodologically safer system feel fachlich slower than an experienced palaeographer/editor/historian, because the specialist carries compressed experiential knowledge that immediately narrows hypotheses and identifies diagnostic comparisons.

### Operational consequence — what NOT to build

Do **not** create another competence map, discipline ontology, role framework, generic knowledge-base architecture or METHOD layer from this finding. Those would duplicate already-existing semantics and recreate the process-overgrowth risk identified earlier in #129/#138.

Likewise do not interpret this audit as authorization for bulk corpus ingestion, automatic lexical completion, default HTR, an A+B ensemble, or a persistent candidate truth store.

### Proposed bounded next meta-test

If the Human Owner chooses to interrupt the current manuscript cursor for this purpose, the smallest useful review is a **Competence Availability / Knowledge Access audit** against the already-existing Requirements and real research fixtures, rather than another competence-modeling exercise.

Use A–F4 plus the prepared G problem as fixtures and ask for each consequential expert move:

`research decision/problem`
→ `which already-defined competence is implicated?`
→ `what specialist/experiential knowledge would an expert likely activate?`
→ `was that knowledge actually available in the executed workflow?`
→ `how was its absence compensated (manual search, broad comparanda, tooling, repeated inspection)?`
→ `what did that cost?`
→ `which external resource class could supply it?`
→ `can the exact contribution be inspected/cited/reproduced?`
→ `does it produce a better graphically testable question or search route?`
→ `when may it be activated without becoming source-reading authority?`

The desired output is a **prioritized list of demonstrated Knowledge-Access gaps**, not a new ontology.

### Evaluation dimensions

For any candidate resource/access path, prefer measuring:

- **knowledge latency** — time/steps from recognizing a domain problem to obtaining relevant specialist information;
- **diagnostic leverage** — whether the information improves the next discriminating question;
- **search-space reduction** — whether it removes plausible dead ends or prioritizes better comparanda;
- **traceability** — whether the actual specialist source/example used is recoverable and citable;
- **contamination risk** — whether activation timing preserves the distinction between hypothesis generation and source evidence;
- **reuse value** — whether the competence aid has demonstrated value beyond one isolated locus.

A URL, installed tool or named reference does not by itself count as operational competence. A stronger availability chain is approximately:

`known → findable → accessible → actually inspected/citable → translated into a diagnostic question/search strategy`.

### Relation to the existing candidate/evidence tooling

The current `blind → explore → adjudicate` Evidence-Packet boundary is conceptually compatible with this diagnosis. The #145 correction deliberately left candidate sources unactivated by default; that was appropriate for scope/contamination control.

The next question is therefore not whether to weaken the Evidence boundary, but which qualified knowledge sources should be **selectively activatable in explore/domain reasoning** after source-only observation, while retaining Target Return and zero diplomatic authority for external candidates.

In practical terms, the current packet/tooling is epistemically controlled but can be **fachlich under-supplied**.

### Relation to #143

Issue #143 remains useful but should stay bounded to its existing lexical/genre-corpus and reuse-rights purpose. Do not inflate it into the general competence architecture.

The broader Knowledge-Access problem may include, depending on demonstrated fixture need: palaeographic/script reference collections, abbreviature resources, historical-language dictionaries/corpora, comparable scholarly editions and visitation corpora, diplomatics/record-form references, ecclesiastical/administrative/legal/economic regional history, onomastic/toponymic resources, metrology/accounting literature, and specialized retrieval/image/HTR aids.

Selection should follow demonstrated expert-move gaps rather than resource availability.

### Prospective fixture: G / `63r-L04`

G remains a particularly useful prospective fixture because the canonical research plan already requires fresh p17 readiness and a source-first test of the display-capital morphology before candidate/comparator activation.

After that source-only observation is frozen, a competent domain-access step could legitimately generate testable questions from historical display-letter forms, historical lexical variants, visitation-record heading/formula conventions, administrative document structure, same-archive parallels or suitable scholarly editions. None of these may force the reading; their value is whether they identify a smaller and better set of target-checkable discriminators.

### Strategic disposition

**Retain the current epistemic method. Improve the supply of qualified, traceable specialist knowledge into the hypothesis/search stage.**

The strategic sequence suggested by this audit is:

`existing competence requirements`
→ `real A–G expert-move fixtures`
→ `demonstrated Knowledge-Access gaps`
→ `targeted external-resource/tool research`
→ `small number of qualified access paths`
→ `prospective evaluation on unresolved real work`
→ `durable integration only after repeated demonstrated value`.

This **refines**, rather than replaces, the previous #129 finding: the major risk is still governance/tooling growth that displaces source research. The corresponding corrective principle is now more precise — do not add more competence governance where competence routing already exists; invest effort where demonstrated research cases show insufficient access to real specialist knowledge.
