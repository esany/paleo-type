## Text

Completes the act/protocol correction symmetrically across the Knau source group after archival-context verification.

Core result: the project uses **four protocol/source records from three parent archival acts**.

- Reg. Ii 4 Bd. II: parent act `Visitation in Thüringen` → source/protocol `Visitation im Amt Ziegenrück`, fol. 294r–313r.
- Reg. Ii 5: parent act `Registratur für die Superintendenz Neustadt an der Orla (Auszug)` → source/protocol `Visitation im Amt Ziegenrück`, fol. 55v–66v.
- Reg. Ii 3: parent act `Visitation in Jena, Neustadt an der Orla, Pößneck, Saalfeld` → source/protocol `Visitation in Neustadt an der Orla`, fol. 41r–63v, and separately → `Pfarreinkommen Gössitz, Knau ...`, fol. 303r–306r.

Lean model: `corpus/archival-acts.tsv` owns parent acts; `corpus/sources.tsv` continues to own the four protocol/source records used by projects. This avoids a redundant extra source-unit table while preserving the missing archival level.

The correction is applied across files, project source register, inspection/source audit, relationships/events, crosswalk boundaries, resolver/validator, templates, README/AGENTS, methodology and project STATUS/LEARNINGS. The source contract explicitly validates source → parent-act references, including two distinct Reg. Ii 3 sources under one act.

URN policy remains conservative: the six institutionally evidenced Reg. Ii 4 Bd. II image URNs are retained; no URN is synthesized for Reg. Ii 5 or Reg. Ii 3 from identifier patterns.

No database, importer, UI or transcription migration is introduced.
