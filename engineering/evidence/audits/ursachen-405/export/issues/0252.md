## Problem / Gap
paleo-type currently stores several prompts/work instructions among heterogeneous `requirements/` artifacts, while the Human repeatedly needs copy-ready prompts assembled from current repo context. `esany/Wissensarbeit` has a bounded `.prompt` Skill candidate specifically designed to create/review/test prompts without becoming a planner or authority layer.

## Comparator provenance
Fresh comparator: `esany/Wissensarbeit@b448915cf774c573dbf82cf2e17bcb03c10a9ed8`, `skills/prompt/{skill.md,CONTRACT.md,references/core-method.md}`.

Important comparator limit: the Wissensarbeit Skill is itself a **candidate**, executable with real-use evidence but not regression-protected, not Generic-Fit and not authority. Copying it 1:1 would be authority laundering.

## Required effect
Derive a paleo-type-specific candidate preserving at least:
- `.prompt` = return a copy-ready prompt for the following task; do not execute it;
- `.prompt review` = review/improve a supplied prompt;
- `.prompt test` = evaluate result/prompt behavior with explicit judgement-vs-proof boundary;
- thin layer, not orchestrator/planner;
- smallest sufficient instruction, fidelity before token savings;
- derive-before-asking and capability admission;
- repo target/authority checks for repo prompts;
- internal review is not independent;
- candidate output creates no authority/priority/admission;
- status such as `declared`/untested remains visible where useful, without importing incompatible vocabularies blindly.

## Findings covered
F20, F21, F23, F27 plus new finding F40: prompts/work instructions are a real information class but currently mixed with Requirements/audit evidence and lack a bounded reusable interaction contract.

## Next activity / readiness
**READY TO ADAPT/DESIGN AND TEST AS A NON-AUTHORITATIVE CANDIDATE. OPERATIONAL REPO-WIDE SKILL ACTIVATION REQUIRES MATERIALITY/GENERIC-FIT REVIEW.**

## Dependencies
#247 context/applicability, #251 prompt information-class disposition, current D-016 boundary.

## Acceptance / close condition
- adapted contract is copy-ready, paleo-type-specific and provenance-linked;
- prompt creation does not execute the task or write repo state;
- no planning/authority/context-compilation responsibilities are smuggled into the skill;
- at least representative prompt creation/review cases test whether it reduces Human construction burden without mega-prompts/context loss;
- decision records whether operational activation is routine or D-016-material;
- Prompt != Requirement != Plan != METHOD != Current State != Decision remains explicit.

## Non-goals
No copy of Wissensarbeit product authority, no universal Skill framework, no automatic execution after `.prompt`, no prompt as replacement for repository architecture.

## Whole-system return
Report whether the capability earns adoption, what prompt artifacts can leave `requirements/`, and what Human/Agent workflow burden changes.
