## Critical distinction

The current workflow must distinguish:

```text
RETRIEVABLE
an authorized connector/tool can obtain image bytes

STAGED
those bytes have been delivered to the target work context

VISION-INSPECTABLE
the target Source Research context can actually inspect the manuscript pixels
```

`retrieval succeeded` MUST NOT be used as a synonym for `Source Research can now see the image`.

For visual scholarly work the required gate is:

`exact evidence identified + authorized + staged + vision-inspectable in target role`.

## Terminology correction after live handoff review

The feasibility result remains valid, but one label in the recorded Option-C path is too compressed for reuse across heterogeneous models.

Where the earlier comment says:

```text
verify that the target context can inspect pixels
→ record EVIDENCE STAGED = PASS
```

read the reusable state semantics as:

```text
STAGED = PASS
→ VISION-INSPECTABLE = PASS
→ VISUAL EVIDENCE READY = PASS
```

for the same evidence object in the same target context.

`STAGED` alone is the target-object-presence state; `VISUAL EVIDENCE READY` is the derived execution gate for visual Source Research. `RETRIEVABLE` implies neither.

This supersedes only the ambiguous shorthand, not the #85 technical finding that the current decisive cross-chat staging boundary is outside demonstrated repo-side capability and that no resolver/helper is justified now.
