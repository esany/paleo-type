## Real demonstrated gap
For `THHSTAW-EGA-REG-II-3-PROT-NEUSTADT-41R-63V` the repository currently has:
- canonical Source identity and extent `41r–63v`;
- exact inspected archive export and SHA-256 in `corpus/files.tsv`;
- project inspection evidence confirming that the inspected export is a 47-page export spanning protocol folios 41r–63v;
- **no canonical source-wide `corpus/source-data/<source_id>/crosswalk.tsv`**.

That means folio ↔ export/image/PDF-page relocation still depends on knowledge not fully represented in the reusable Source layer. This is the primary problem owned by this Issue.

## Planned work after explicit scheduling/admission
The intended bounded execution chain is:

```text
exact inspected 47-page export
        ↓
evidenced page/folio reconstruction
        ↓
corpus/source-data/
THHSTAW-EGA-REG-II-3-PROT-NEUSTADT-41R-63V/
crosswalk.tsv
```

Reconstruct the Neustadt source-wide crosswalk from the exact inspected export and/or authoritative provider evidence.

For each evidenced mapping preserve as applicable:
- canonical Source ID;
- archival folio;
- export/image identifier;
- PDF page;
- mapping status/evidence;
- content anchor/notes when useful for verification;
- stable image URN only if authoritative evidence actually supplies one.

The reconstruction must be evidence-led rather than sequence-guessed: use directly visible foliation, controlled recto/verso progression, export/PDF ordering and other inspectable anchors only where they support the mapping. Mark uncertainty explicitly rather than filling gaps by inference.

Do not assign adjacent material outside the evidenced Source boundary.

## Persistent image URNs are optional enrichment, not completeness target
Current state:
- Reg. Ii 4 Bd. II 306v–309r already has institutionally evidenced per-image URNs — retain them;
- Reg. Ii 5 has a usable folio↔export-image↔PDF-page crosswalk but no recorded per-image URNs;
- Reg. Ii 3 / Pfarreinkommen has a usable folio↔export-image↔PDF-page crosswalk but no recorded per-image URNs.

Missing URNs for Reg. Ii 5 or C2 do **not** constitute a separate implementation target by themselves.

If authoritative URNs are encountered during legitimate Source-access work, they may later be added as provenance. If they are not evidenced, they remain absent.

Never:
- synthesize URNs from neighboring identifiers;
- extrapolate provider patterns;
- treat URL/URN as equivalent to the exact checksum-controlled export;
- make URN presence a condition for Source validity or crosswalk usefulness.
