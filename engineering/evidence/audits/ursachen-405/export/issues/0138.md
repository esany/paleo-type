## Anlass

Vor der nächsten Manuskriptphase F1 in #123 soll die reale Ausführung der bereits abgeschlossenen Cluster A–E5 als begrenzte Stichprobe darauf geprüft werden, wo `paleo-type` wissenschaftlich notwendige Wiederholung mit technisch/prozessual unnötiger Wiederholung koppelt.

Das ist **kein allgemeines Refactoring aus Geschmacksgründen** und kein neuer Research-Owner. Der aktuelle `main`-Stand `0583665e0663e65a9005da18d6f9cb9f677204bd` liefert konkrete Failure Fixtures:

- `projects/ega-reg-ii-5-knau/STATUS.md` trägt inzwischen wiederholt clusterhistorische SHA-/Crosswalk-/Render-/`STAGED`-/`VISION-INSPECTABLE`-Details, obwohl der ausführliche Evidenzpfad bereits in `research/internal-comparanda-relecture-61v-63r.md` liegt;
- mehrere `transcription/first-reading/*.tsv`-`evidence_note`s enthalten Mini-Audits mit Renderauflösung, Comparator-Reihenfolge und generischer Methodendisziplin zusätzlich zum Research-Owner;
- identische SHA-/Crosswalk-/Render-/Crop-Arbeit wurde in mehreren A–E5-Ausführungen erneut hergestellt, obwohl ein Teil davon deterministisch und prinzipiell wiederverwendbar ist;
- Cluster A hat Source-Durchsicht bezahlt, deren technische Such-/Crop-Ergebnisse heute nur schwer derivativ wiederverwendbar sind;
- `62r-L19` zeigt als adversarial Failure Fixture, dass ein geerbter vermeintlich sicherer Anchor (`80`) die spätere Frage selbst verengen kann.

Canonical maintenance rule: `methodology/maintenance.md` — one fact, one canonical home; derive/reference rather than copy; propagate only changed consequences; then return to research.

## Ziel

Für wiederkehrende Schritte aus A–E5 belastbar unterscheiden:

- **KEEP** — epistemisch notwendige erneute fachliche Beurteilung;
- **DERIVE/REUSE** — deterministisch wiederverwendbar, cachebar oder aus kanonischen Ownern ableitbar;
- **COLLAPSE** — redundante Persistenz/Boilerplate ohne eigenen Wahrheitsgehalt.

Der Audit implementiert noch keine größere Workflow- oder Schemaänderung. Er bestimmt nur, welche Kosten wissenschaftlich notwendig sind, welche technisch wiederverwendet werden können und welche Persistenz zusammengezogen werden sollte.

## Leitfragen pro Schritt

1. **Muss das erneut fachlich beurteilt werden?**
2. **Muss das erneut maschinell berechnet werden?**
3. **Muss dieses Resultat erneut persistiert werden?**
4. **Reicht ein Verweis auf bereits autorisierte Wahrheit?**
5. **Welches konkrete Ereignis macht Wiederverwendung ungültig?**

Zusätzlich für jede vorgeschlagene Änderung:

- **routine maintenance/tooling** oder
- **material research-system change** nach `methodology/maintenance.md`?

## Audit-Matrix

Für jeden wiederkehrenden A–E5-Schritt mindestens diese Felder erfassen:

| Feld | Inhalt |
|---|---|
| wissenschaftliche Funktion | welche epistemische/provenienzbezogene Invariante geschützt wird |
| heutige Ausführung | was A–E5 real tun |
| Wiederholungskosten | Modellkontext, Hashing, Rendering, Suche, Persistenz, PR/CI etc. |
| kanonischer Owner | wo die resultierende Wahrheit hingehört |
| artifact reusable? | ob das technische Artefakt unverändert wiederverwendbar ist |
| claim reusable? | ob die fachliche Aussage selbst wiederverwendbar ist |
| reuse/invalidation rule | konkrete Gültigkeits- und Invalidierungsbedingungen |
| disposition | `KEEP` / `DERIVE-REUSE` / `COLLAPSE` |
| change class | routine oder material |

## Zu schützende epistemische Wiederholungen

Diese dürfen nicht als „Redundanz“ weggeoptimiert werden:

- source-only / blind Observation **vor** Kandidatenkontakt;
- Rückkehr zum Zielgraphen nach Exploration;
- erneute fachliche Bewertung jedes tatsächlich verwendeten Comparandums;
- sichtbare Restunsicherheit und negative Ergebnisse;
- adversarial reopening eines vermeintlich sicheren Anchors bei konkreter viable Alternative;
- wissenschaftliches Result Review.

`COLLAPSE` darf niemals einzigartige Evidenz löschen.

## Kandidaten für DERIVE/REUSE

Explizit prüfen:

- File-Digest/SHA-Verifikation;
- Crosswalk-Auflösung;
- reproduzierbare Page-Renders;
- Crop-Erzeugung;
- derived witness view;
- Zusammenstellung kanonischer Kontextdaten;
- technische Source-/File-Metadaten;
- ggf. Fixture-/Test-Propagation;
- derivativer Comparator-/Crop-Index als Suchbeschleuniger.

Für Render-Reuse mindestens prüfen:

`source-file digest + PDF page + renderer/version + rendering parameters`

Für Crop-Reuse anschließend mindestens:

`render digest + crop coordinates/transform`.

Wichtig: Ein wiederverwendbares Artefakt erzeugt **keinen persistenten wissenschaftlichen PASS**. `VISION-INSPECTABLE` bleibt kontextspezifisch: ein neuer scholarly context muss die relevanten Pixel tatsächlich sehen können, aber nicht zwingend denselben Render erneut berechnen.

## Kandidaten für COLLAPSE

Explizit prüfen:

- historische Clusterchronik in `STATUS.md`, soweit sie den vollständigen Research-Audit dupliziert;
- generische Methodendisziplin/Render-Boilerplate in TSV-`evidence_note`s;
- redundante Wiedergabe derselben Forschungsentscheidung in STATUS + Research-Audit + TSV + Issue/PR;
- PR-/CI-Granularität als Default für einzelne Wortkanten statt kohärenter Adjudication Packets.

Zielbild für Ownership:

- `STATUS.md` = gegenwärtiger Forschungs-/Gate-/Access-/Restart-State + autorisierte Next Action;
- `transcription/first-reading/*.tsv` = gegenwärtige diplomatische Wahrheit je Locus + knappe zeilenspezifische Evidenz;
- `research/internal-comparanda-relecture-61v-63r.md` = vollständiger Entscheidungs-/Evidenzpfad;
- derived views = deterministisch rebuildable;
- Issues/PRs = Arbeit/Review, nicht Forschungstruth;
- caches/indexes = disposable/rebuildable technische Beschleuniger.

## Failure Fixtures

Mindestens diese vier Fälle verwenden:

1. **E1–E5 STATUS:** wiederholte SHA-/Render-/Readiness-Prosa;
2. **E1–E5 TSVs:** lange Mini-Audits in `evidence_note`;
3. **Cluster A:** bereits bezahlte Source-Durchsicht und Frage nach derivativer Wiederverwendung;
4. **62r-L19 `80`:** geerbter Anchor als adversarial Beispiel für eine Sicherheitsimplementierung, die eine falsifizierende Frage zu früh verengen kann.

Der vierte Fall ist kein Auftrag, die Lesung in diesem Audit zu ändern. Er dient dazu, zwischen Schutzinvariante und unnötig enger Implementierung zu unterscheiden.

## Sicherheitsregel-Audit

Nicht fragen: „Welche Sicherheitsregeln können weg?“

Stattdessen für jeden teuren Schritt:

> Welche epistemische Invariante wollen wir schützen, und welche konkrete Implementierung dieser Invariante ist unnötig teuer?

Beispiele:

- Exact evidence identity = Invariante; PDF für jeden Cluster neu hashen = mögliche Implementierung.
- Reproducible target image = Invariante; identische p15-Renders wiederholt neu erzeugen = mögliche Implementierung.
- Candidate darf Reading nicht diktieren = Invariante; Candidate Generation generell bis nach jeder internen Suche verbieten = nicht automatisch notwendige Konsequenz.
- Target return after candidate contact = Invariante; eigener PR pro Wortkante = nicht notwendige Konsequenz.

### Core finding

The main cost is not merely prose boilerplate. A significant amplification path exists:

`Research detail → STATUS.md copy/history → tools/project_context.py copies full STATUS text → regression tests pin volatile STATUS phrases → next micro-reading repeats STATUS/fixture/PR/CI propagation`

Observed audit measurements at this checkpoint:

- `STATUS.md`: 39,479 bytes;
- bounded #123 research owner `research/internal-comparanda-relecture-61v-63r.md`: 77,545 bytes;
- `tools/project_context.py` exposes the complete STATUS text in `canonical_status.text` rather than a lean current-state projection;
- `test_project_context.py` / `test_recovery_assurance.py` pin parts of historical cluster/readiness prose, making volatile restart history behave like a textual interface.

This means STATUS inflation directly becomes restart-context/token inflation and then creates fixture-maintenance pressure.

### Audit dispositions

#### KEEP — epistemically necessary repeated judgement

- current staged-byte equality check against the canonical File digest when the execution artefact/context changes;
- `STAGED` and especially `VISION-INSPECTABLE` as execution-/target-context claims;
- source-only / blind observation before candidate contact;
- candidate/comparandum scholarly evaluation;
- return to the target graph after exploration;
- residual uncertainty and negative search outcomes;
- adversarial reopening of a working/inherited anchor when a concrete viable alternative appears;
- result review.

These are independent epistemic acts, not redundant implementation.

#### DERIVE/REUSE — deterministic/rebuildable technical work

- canonical File digest as Corpus truth;
- folio ↔ export-image ↔ PDF-page crosswalk until its owner changes/is challenged;
- page renders keyed at minimum by `source-file digest + PDF page + renderer/version + rendering parameters`;
- crops keyed by `render digest + crop coordinates/transform`;
- derived witness view;
- canonical Source/File/context metadata assembly;
- disposable/rebuildable comparator/crop retrieval aids.

Critical distinction: **artefact reuse does not imply claim reuse**. A p15 render may be reusable while `VISION-INSPECTABLE` and the scholarly judgement made from it remain context-specific. Likewise an old crop may be reusable while an old `no comparator found` result is reusable only for the same feature/search question and evidence state.

#### COLLAPSE / REFINE — duplicated persistence/process

- cluster-by-cluster SHA/render/readiness chronology in `STATUS.md` where the full path already lives in the bounded research owner;
- generic exact-SHA / 600-dpi / target-first / exclusion boilerplate in TSV `evidence_note`s, while preserving unique line-specific evidence and a pointer to the full audit;
- repeated statement of the same result across research owner + STATUS + TSV + Issue/PR prose;
- default PR/CI/cursor/fixture cycle for each microscopic word-edge decision where several decisions belong to one coherent adjudication packet;
- regression assertions that treat volatile historical STATUS prose as a stable API contract.

Do **not** auto-generate regression expectations from the current STATUS text: that would turn assurance into self-confirmation. Tests should protect independent stable invariants.

### Failure fixtures confirmed

1. **E1–E5 STATUS inflation:** repeated File identity, crosswalk, p15 rendering and readiness narrative.
2. **E1–E5 TSV persistence inflation:** real line evidence mixed with repeated method/readiness mini-audits.
3. **Cluster A reuse boundary:** technical pages/renders/crops can be reused; the negative scholarly result cannot be generalized from the original surname-feature question to arbitrary later questions.
4. **`62r-L19 80`:** WP-R1 inherited `80` as secure, which narrowed E5 to the following token. A later viable `So` hypothesis shows why adversarial reopening of inherited/working anchors must remain possible. This audit does not itself change the TSV reading.

### Change-class result

Likely **routine/corrective maintenance**:

- STATUS deduplication while preserving current restart/gate/access/cursor truth;
- shortening TSV evidence notes to line-specific evidence + research-owner reference;
- batching coherent adjudications into one research PR where appropriate;
- read-only/rebuildable technical render/crop reuse that creates no new evidence authority.

Requires separate material/consequential admission/review before implementation:

- changing the established `tools/project_context.py` output contract / what canonical restart context means;
- introducing a canonical persistent render/crop registry or new evidence owner;
- materially changing what CI/recovery assurance certifies.

The audit acceptance criteria are therefore met. F1 remains the canonical #123 scholarly cursor until a later canonical change; no F1 manuscript work was performed by this review.
