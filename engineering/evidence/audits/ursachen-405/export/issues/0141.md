## Post-#145 first-run constraint

The first #141 experiment is **strictly same-source**. Its initial candidate pool is only the active Reg. Ii 5 Source, fol. 55v–66v. Reg. Ii 4 / G4 is not enabled in the first retrieval run and is not injected through the Evidence Packet.

An external-witness pool may be reconsidered only later as a separately activated candidate source after the same-source experiment has been evaluated. Mere availability or an existing G4 mapping is not activation authority.

This makes the first experiment cleaner: if visual retrieval adds no useful palaeographic candidate breadth inside Reg. Ii 5, that result is interpretable without a cross-witness confound.

## Purpose

Prototype a **local, derived visual-retrieval helper** that can propose graphically similar line/word/sign crops for a difficult target locus without creating a new canonical palaeography lexicon or treating visual similarity as reading evidence.

This issue responds to a demonstrated weakness in the current #123 workflow: for dense `62v` unresolved spans, the method requires a concrete visible discriminator before a broader comparator search, but unaided target inspection may not always expose a sufficiently specific feature.

Desired role:

```text
exact target crop
→ retrieve visually similar same-source candidate crops
→ inspect exact returned loci
→ formulate/test a palaeographic discriminator
→ return to target graph
→ promote only if target graph carries the reading
```

## Scientific boundary

The retrieval index is a **candidate generator only**.

It must not imply:

- same word;
- same hand;
- same scribe;
- same person/place;
- same value/unit;
- diplomatic reading authority.

`same Source` remains distinct from `same hand`, and similarity ranking is not independent confirmation.

The canonical diplomatic owners remain the existing folio-local `transcription/first-reading/*.tsv` files. This helper must be fully rebuildable from exact source derivatives and metadata.

## Why this may outperform manual source browsing

Current #123 deliberately forbids source-wide lexical fishing. A visual nearest-neighbour/helper can preserve that safeguard while making the search **feature-driven but machine-assisted**:

- crop the exact unresolved target or stable subspan;
- search only the explicitly activated authorized pool;
- return a small top-k set with exact provenance;
- inspect those few candidates rather than repeatedly browsing all folia manually.

This restores exploratory breadth without allowing the retrieval system to supply text.

## Candidate-selection states

The experiment must make these states distinguishable:

`pool available ≠ pool activated ≠ crop returned ≠ crop scholarly-inspected ≠ comparator accepted ≠ reading promoted`

A retrieval score/rank is technical metadata only.

## Initial candidate pools

### First run — authorized

1. **same Reg. Ii 5 Source, fol. 55v–66v only**.

### Deferred — not activated in first run

2. Reg. Ii 4 / other witness pools;
3. broader corpus pools.

Do not silently mix pools. Every returned candidate must expose canonical Source/File/locus provenance and pool class.

## Dependency on #142

#142 first measures and confirms the neutral Evidence Packet/context boundary. #141 then plugs in only as an **explicitly activated same-source generator**. It must not modify the default packet so that retrieval is automatically run merely because the helper is installed or available.

## Prototype constraints

Prefer a zero-recurring-cost local stack using existing Python/image tooling and an open model/feature extractor whose license is recorded before adoption.

No vector database or service is required for the spike. A small local index/file is sufficient if deterministic and rebuildable.

Possible unit types to evaluate:

- physical-line crops;
- word/span crops where segmentation is reliable;
- isolated numeral/sign crops for notation problems.

The spike should determine which granularity actually helps; do not assume one universal segmentation model.

## Evaluation controls

Use known repeated/secure forms as retrieval sanity checks, for example where exact target crops exist:

- recurrent `wolff`;
- `pfarrer/pfarrern` forms;
- repeated surname-like graph only as a recurrence control, **not** as settled spelling or same-hand evidence;
- selected numeral/sign shapes from the 61v accounting block;
- hard unresolved `62v` targets only after the earlier control experiment demonstrates value and fresh target readiness is established under #123.

Evaluate whether correct/usable same-source comparanda appear in a small top-k set and whether returned examples expose discriminating letter/sign features rather than merely overall word silhouette.

## Required provenance per retrieval result

At minimum:

- canonical Source ID;
- File ID / derivative provenance;
- folio and recoverable local locator;
- crop coordinates or deterministic crop recipe where applicable;
- feature/index version;
- similarity score/rank as a technical value only;
- pool (`same-source` in the first run).

## Evaluation question

The success criterion is not generic image-similarity quality. Ask whether same-source retrieval produces **new, graphically useful, inspectable comparanda** that reduce blind manual browsing while preserving target-return and reading authority.

False/silhouette-only matches must be recorded rather than hidden.

## Non-goals

- no Reg. Ii 4 / G4 pool in the first run;
- no new canonical `palaeography/lexicon.tsv`;
- no source-wide diplomatic transcription just to populate the index;
- no implicit same-hand clustering;
- no automatic word recognition/promotion;
- no semantic clause reconstruction;
- no platform/database architecture unless a later demonstrated scale need requires it.

## Definition of Done

- [ ] #142 neutral packet/context measurement has established the integration boundary;
- [ ] a minimal local prototype can take an exact target crop and return a small ranked set from **Reg. Ii 5 only**;
- [ ] benchmark controls show whether retrieval gives useful palaeographic comparanda beyond manual browsing;
- [ ] candidate-selection states remain explicit and no pool is auto-activated by availability;
- [ ] false/silhouette-only matches and scientific limitations are documented;
- [ ] index/model/license and rebuild recipe are explicit;
- [ ] a keep/drop decision is recorded;
- [ ] no canonical reading is changed solely because of similarity retrieval.

## Phase-2 evaluation refinement after #142

#142 is now complete and establishes the neutral packet/context boundary. The first #141 run therefore remains strictly **same-source Reg. Ii 5, fol. 55v–66v**, with no Reg. Ii 4/G4, lexicon/genre context, or HTR.

The first visual-retrieval evaluation should record two additional cross-generator metrics so #140 can later be compared on the same basis:

1. **candidate utility per inspected result** — among an explicitly bounded top-k actually inspected, how many returned loci provide a genuinely useful graphical comparator/discriminator for the target question? Similar-looking but non-discriminating/silhouette-only results count as non-useful, not hidden failures.
2. **cost to first useful discriminator** — at minimum record retrieval runtime plus the rank/number of candidates that had to be inspected before the first useful discriminator appeared. Human inspection wall-clock/context cost should be recorded where it can be measured without false precision; otherwise mark it unmeasured rather than estimate it.

The experiment's success condition remains scholarly, not image-retrieval vanity quality: a result becomes relevant only after direct visual inspection of the returned locus, and any later reading consequence still requires target return. `No useful comparator in top-k` is a valid NO-GO/REFINE result.

Shared phase-2 principle: `smallest sufficient current state + maximally useful search breadth + unchanged evidence authority`, with `available pool ≠ activated pool ≠ crop returned ≠ crop inspected ≠ comparator accepted ≠ reading promoted` kept explicit.

F1 remains untouched and is reserved for the later real comparison after Generator A and Generator B have bounded results.
