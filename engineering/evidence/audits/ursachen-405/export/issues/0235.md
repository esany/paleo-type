## Purpose

Persist a repository-first audit of how paleo-type can stop using the Human Owner as a routine relay/dispatcher once no material Human-owned question remains, and compare current `esany/Wissensarbeit` lifecycle/context/token-efficiency evidence.

This PR is **analysis/navigation only**. It does not change METHOD, Project scholarly state, Source/File truth, D-016 admission, package/runtime architecture, or implementation authority.

## Main findings

- Current paleo-type governance already says routine bounded work belongs to AI/tooling; the remaining Human-proxy failure is mainly an operational continuation/context gap.
- Planning/analysis/research/concept/design are substantive work, not merely pre-implementation ceremony. The lifecycle should therefore be phase-neutral rather than implementation-centric, without becoming a mandatory waterfall.
- `Wissensarbeit` provides strong comparative properties: `Human-in-the-loop, not human-as-workflow-engine`, a small fail-closed execution cursor, bounded context compilation, derive-before-asking, externalize-before-compaction, quality-preserving scarce-mode routing, and delta/evidence return semantics.
- The best-supported architecture remains the existing Class-B lifecycle direction. Refine IC-01/03/06 with authorized-work continuation, `decision-needed` semantics, applicability-bounded context and Human-relay qualification; keep IC-02 as current/history/supersession support.
- A minimal persisted execution cursor/harness remains conditional. First test whether current GitHub work owner + repository canonical owners can derive enough operational state. No universal workflow engine or autonomous planner is justified.
- Context-cost evidence: root governance/orientation surfaces are ~67k characters and current methodology files ~144k characters; indiscriminate loading is therefore >210k characters before Project/Issue/evidence state. The target is to reduce reconstruction, not evidence.

## D-016 consequence
