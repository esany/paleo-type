## Human need / why this audit now

Recent real source work on Sächsisches Staatsarchiv 20578 Nr. 632 shows that the repository now has comparatively mature scholarly rules, Source/File provenance, crosswalks, evidence semantics, Project state and quality gates. The remaining friction is increasingly about **how reliably and efficiently those pieces compose during real source work**.

The practical question is no longer simply `do we have the right rules?`, but:

> **Which parts of the current tool/repository workflow genuinely protect scholarly quality, which clerical/provenance tasks should become deterministic, where are top-down and bottom-up movements still too rigid, and where can process overhead be removed without weakening evidence, provenance, uncertainty or Human control?**

The immediate objective is therefore a **larger inventory of the existing toolchain and source-work flow before redesign**.

## Starting hypothesis — to test, not implement

Current experience suggests a useful separation:

```text
scholarly judgement should remain adaptive and evidence-led
while
clerical / provenance / coverage / restart work should become as deterministic as possible
```

Likewise, G1–G6 should be examined as **scope- and evidence-relative quality states**, not assumed to require a rigid one-way execution pipeline where real source work legitimately iterates between structure discovery, pilot reading, scope formation, transcription and palaeographic testing.

These are hypotheses for audit/falsification. They are not a pre-authorized METHOD change.

## Candidate deterministic capabilities to assess

Do **not** build these yet. Determine whether current tooling already supplies them, whether they are genuinely needed, and which owner would be correct if a gap is real:

1. **Evidence / locus packet builder**
   - resolve exact Source, File(s), crosswalk locators, Project use/evidence, prior research decisions, coverage and relevant Human corrections for one bounded locus;
   - avoid repeated manual context assembly.

2. **Transcription dataset + validator**
   - provide the smallest operational representation that satisfies existing G2/transcription semantics;
   - validate provenance/structure mechanically without judging whether a grapheme was read correctly.

3. **Coverage / uncertainty analyzer**
   - distinguish represented, unresolved, illegible, variant and not-yet-represented source units inside a declared scope;
   - generate a targeted uncertainty queue rather than rereading everything.

4. **Human-readable diplomatic-view generator**
   - derive the audit-friendly witness view from canonical transcription data;
   - no manually maintained second text truth.

5. **Gate-readiness report**
   - report machine-checkable prerequisites/completeness/known residuals;
   - must never convert deterministic readiness into manuscript truth, specialist validation or automatic scholarly gate acceptance.

## Simplification / decommission audit

Also look explicitly for work that can be removed or reduced **without losing scholarly quality**:

- repeated GitHub micro-handoffs that do not change durable state;
- repeated manual reconstruction of Source/File/crosswalk context;
- duplicate/stale orientation prose that should be derived;
- loading broad governance/context when a bounded executable projection can preserve all applicable rules;
- status/checkpoint chatter that does not own changed truth;
- repeated full-document inspection when a mechanically generated unresolved/consequential-locus queue would suffice;
- any parallel truth store that can be replaced by a generated view.

Do **not** simplify away:

- evidence provenance;
- Source/File distinction;
- archival/digital locator distinction;
- observation/reading/normalization/identification/interpretation separation;
- document form versus transmission stage;
- uncertainty and rejected alternatives where consequential;
- Human Owner authority;
- independent specialist-validation boundary;
- restartability and exact return to canonical owners.

## Top-down / bottom-up movement audit

- Can a large composite file remain broad at reconnaissance level while only selected units receive G2–G6 depth?
