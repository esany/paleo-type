## Demonstrated gap

`corpus/sources.tsv` currently has one `document_type` field. Existing data already combines different semantic dimensions in that field, for example:

- `Visitationsprotokoll / Auszug — source group`;
- `Visitationsprotokoll — source group`;
- `Pfarreinkommen / Einkommensverzeichnis — source group`.

The domain requirement inventory already marks this as a real risk:

- **REQ-ARCH-010:** documentary form/genre and record stage/status must be distinguishable where stage is consequential;
- current support: `risk / partial`;
- demonstrated danger: original/copy/extract/draft status can be conflated with genre/form.

The Wolkenburg material triggers this gap directly: some Archivalien may contain later copies/extracts of older Knau-related documents originating in earlier documentary contexts.

## Why this matters

These are distinct questions:

1. **What kind of document is this?** — e.g. Lehnsbrief, Kaufvertrag, Gerichtsakte, Familienchronik, Protokoll, Rechnung;
2. **What transmission/record stage is this witness?** — e.g. original, draft, copy, certified copy, extract, later transcript, compilation;
3. **What relation does it have to another Source?** — e.g. copy of, extract from, textually corresponds to;
4. **What does the finding aid say versus what has been established by inspection?**

Collapsing these into one free-text `document_type` value makes it easy to turn a transmission statement into a genre, inherit a catalogue label into the manuscript, or treat a copy as if it were the original documentary event record.

## Kommentar 5985667584 · 2026-10-04T23:39:08Z · esany

## Wolkenburg refinement — form, Source granularity, transmission stage and condition are separate axes

The Human-Owner clarification in #270 makes this Issue an **integral Wolkenburg requirement**, not merely a later peripheral clean-up. A single Archivale may contain multiple documentary levels and forms: e.g. document complex → letter/charter/general description → section/paragraph/register/accounting overview, while copies/transcripts or fragments introduce further distinctions.

The stable requirement is therefore broader than splitting one `document_type` field into two labels. At least these questions must not be collapsed:

1. **documentary form/function** — e.g. letter, charter/legal record, register, account, general description/compilation;
2. **Source granularity/identity** — whether the thing is itself a canonical Source or merely a locus/substructure;
3. **transmission/record stage** — original-like witness, draft, copy, certified copy, later transcript, extract, compilation, etc. where evidence supports it;
4. **preservation/condition** — e.g. `fragment` when that describes survival/condition rather than documentary genre;
5. **relation to another Source** — copy/extract/textual correspondence/dependence belongs in evidence-bearing relations, not in the form field;
6. **evidence level** — catalogue/finding-aid wording, archival inference and direct inspection remain distinct.

Copies and transcripts also make chronology target-specific: the date of the present witness, the represented earlier act/text, a later copy/excerpt and an event described within it can differ. REQ-HIST-011 already protects that distinction; this Issue must not solve it by overloading form/stage metadata.

### Boundary

Do **not** design a universal diplomatics ontology, fixed Source tree or closed vocabulary here. Use real Wolkenburg fixtures to establish which distinctions are actually necessary and which units need stable Source identity versus locus-only representation. The current `source-and-provenance.md` rule of flexible recursive Source depth remains authoritative.

Any shared Source-contract representation change remains material under D-016. This comment records the requirement/falsification only.
