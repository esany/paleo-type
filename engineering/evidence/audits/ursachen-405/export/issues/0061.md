## Status
**Planning issue only. No Corpus, Contract or relation migration is authorized by this Issue.**

This is a bounded targeted correction for one demonstrated referential problem. It does not define a universal locus/span ontology.

## Demonstrated problem
`corpus/relationships.tsv` REL008 currently encodes source-relative loci inside `subject_id` and `object_id`:

- Reg. Ii 4 Source ID + `:306v-309r`;
- Reg. Ii 5 Source ID + `:61v-63r`.

That conflates two already distinct concepts:
- canonical Source identity;
- source-relative locus of the relationship claim.

It also prevents the relation endpoints from resolving as pure canonical Source IDs.

## Upstream requirements
- REQ-ARCH-006 — Source relationships are evidence-bearing claims;
- REQ-ARCH-009 — consequential loci require unambiguous addressing rather than ad-hoc `source:locus` identity strings;
- REQ-PAL-002 — exact comparison anchors;
- REQ-EDIT-002/005 — source location/order and explicit corresponding-unit mapping;
- REQ-GWP-002 — exact source/file/locus provenance;
- REQ-RSE-004 — deterministic referential integrity.

## Smallest current target
For Source-to-Source relations that address bounded passages, plan a minimal representation such as:

`relation_id | subject_id | subject_locus | predicate | object_id | object_locus | status | evidence_basis | notes`

Rules:
- Source endpoints remain pure canonical Source IDs;
- source-relative loci are separate fields when needed;
- `part_of` normally leaves locus fields empty because it relates Source nodes structurally;
- relation status/evidence basis remain explicit;
- no new graph store, Source hierarchy or relation ontology is introduced.

This is the currently preferred targeted solution because it fixes the demonstrated failure with the least new structure. If implementation planning exposes a still smaller lossless representation, #25's lean rule continues to govern.

## REL008 regression fixture
Any later admitted migration must preserve, without strengthening the claim:
- subject Source = Reg. Ii 4 Bd. II / `00000089`;
- subject locus = `306v-309r`;
- predicate = `textually_corresponds_to`;
- object Source = Reg. Ii 5 / `00000129`;
- object locus = `61v-63r`;
- current `observed` status;
- current evidence basis;
- current limitation: genuine correspondence does not yet prove verbatim copying or complete line-level equivalence.
