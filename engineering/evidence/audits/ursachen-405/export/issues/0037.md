## Governing requirement
AI must function as expert research assistance under scholarly evidence constraints, not as an authority substitute. Human-in-the-loop must be real, role-appropriate and auditable: the non-specialist project owner controls purpose/use, while qualified specialists provide independent validation where consequence warrants it.

## Review criteria — AI architecture
Verify that the system supports:
- task/domain routing so only relevant methodological context is loaded;
- a small set of mandatory invariants plus on-demand specialist instructions rather than uncontrolled prompt growth;
- explicit separation of model output, inspected evidence and independent corroboration;
- no model self-agreement/repetition counted as independent evidence;
- preserved uncertainty, alternatives and refusal to force resolution;
- provenance for consequential AI-assisted transformations/claims without logging every trivial prompt;
- protection against context leakage/semantic completion in blind or palaeographic work;
- deterministic tools/checks for deterministic failure classes rather than relying only on prompt rules;
- representative evaluation before systematic AI/HTR output shapes corpus-level findings;
- documented failure modes, scope limits and re-evaluation after material model/workflow changes;
- privacy, rights and data-access constraints appropriate to source material;
- clear fallback/escalation when tools/models cannot inspect evidence at the required level.

## Review criteria — Human-in-the-loop
Verify that:
- the project owner can see the human-readable source/transcription, uncertainty, evidence, current gate and next action without reading internal TSV/prompt machinery;
- the user is not asked to adjudicate specialist questions they cannot validate;
- user decisions are about purpose, priority, access/rights and consequential use, not routine repository synchronization;
- consequential specialist claims explicitly state whether independent qualified human review occurred;
- expert escalation is targeted by consequence/uncertainty rather than routine ceremonial approval;
- review packets expose exact loci, candidate readings, evidence and unresolved alternatives so an expert can genuinely review rather than trust an AI summary;
- AI-assisted method compliance and independent expert validation remain different statuses.

## Experiential-knowledge check
AI should exploit domain expertise and learned pattern knowledge proactively, but every consequential expert-like judgement must be routed to the relevant discipline and converted into inspectable evidence tests. Tacit knowledge can suggest where to look; it cannot silently manufacture source facts.

## Measures if a gap is demonstrated
Possible minimal measures:
- shrink `AGENTS.md` to true mandatory invariants and route detailed method dynamically/on demand;
- add explicit task/domain routing and context budgets;
- introduce independent adversarial/model review only where it provides genuinely different evidence/testing, not ceremonial duplication;
- add deterministic validators/generators for machine-checkable tasks;
- define representative evaluation sets and error taxonomies if HTR/systematic AI reaches #3 trigger;
- build simple human-readable review surfaces before adding complex agent orchestration;
- formalize expert-review packets/status only when consequential claims require them;
- record model/tool/version only when material to reproducibility or method evaluation.

## Trigger
Review when prompt/governance context becomes hard to manage, the same AI failure recurs despite prose guardrails, multiple models/agents/tools are introduced, systematic AI begins shaping corpus conclusions, a UI/workflow is added, or publication claims rely materially on AI-assisted specialist judgement.

## Definition of Done
- AI responsibilities, user responsibilities and expert-review responsibilities are operationally distinct;
- a non-specialist user can audit the result and uncertainty without becoming the specialist validator;
- deterministic rules are enforced deterministically where justified;
- AI evaluation is representative of actual source tasks and known failure classes;
- model agreement is never mislabeled independent evidence;
- escalation/review is consequence-based and reviewable from exact source evidence;
- the architecture demonstrably improves scholarly work compared with a simpler single-agent/source workflow.

## Do not
Do not add multi-agent orchestration, vector databases, autonomous research loops, model voting or pervasive prompt logging merely because they are fashionable AI patterns. Do not use Human-in-the-loop as a label for making the user confirm decisions they cannot independently assess.

### Write-boundary model for later implementation

1. **Read/analysis** — no durable state change.
2. **Derived write** — rebuildable witness/review/export output; cannot redefine canonical truth.
3. **Canonical research write** — evidence-constrained source/transcription/claim/state maintenance; must preserve provenance/decision history and applicable gates.
4. **Method/architecture change** — cohesive reviewed change traced to requirements.
5. **Governing-objective material change** — proposal only until explicit human owner approval.

The user controls research purpose/priorities, source access/rights facts only they can supply, and consequential publication/use decisions. Routine repo synchronization is not pushed back to the user.

### Evaluation-trigger assessment

Systematic AI/HTR method trigger: **not fired**. The present workflow is source-specific expert assistance. A representative evaluation harness becomes mandatory only when scaled AI outputs materially shape corpus-level findings. The Knau problem cases should nevertheless be retained as future fixtures because they capture known failure classes.

### Architecture handoff

No multi-agent system, vector DB, model voting, autonomous loops or prompt platform is justified. The useful AI architecture is much smaller: deterministic context assembly from canonical owners; consequence-based write boundaries; deterministic checks for deterministic invariants; evidence-preserving uncertainty; and a derived expert-review packet when stakes require it.

Overall: **single-agent/source workflow remains the baseline**; improve its context and control surfaces before adding orchestration.
