## Text

## Research benefit
Catch recurring machine-checkable structural failures before corpus tables become costly to repair.

## Why not now
Observed inconsistencies have mainly been semantic/status drift, not a recurring structural error class. A bounded manual consistency pass is still cheaper than validation infrastructure.

## Trigger
The same machine-checkable structural error class recurs, or an external consumer requires strict validation.

## Definition of Done
- implement the smallest validation that catches the observed error class;
- validate existing lean files rather than replacing them with a database/framework;
- fail clearly on relevant duplicate IDs, broken references and invalid controlled vocabularies;
- derive validation from canonical definitions rather than creating a second truth store.

## Trigger review
Re-check after each bounded consistency pass if a structural error was found, or when an external consumer appears. Otherwise leave deferred.

## Kommentar 5434702636 · 2026-08-27T05:17:36Z · esany

Trigger is now met and the smallest targeted validation has been implemented in PR #51 (merged as `0adcd91b0fd965f31385cc262bb0fdaef18269ab`).

Implemented scope:
- `corpus/source-contract.json` owns stable structural requirements for source/file/project-source/crosswalk records;
- `tools/source_contract.py validate` catches duplicate source/file IDs, duplicate archival identities where record IDs are available, broken source/file/project references, invalid SHA-256/storage/mapping statuses, source-data directory/row mismatches, duplicate loci and invalid/missing digital locators in crosswalk rows;
- `repo-preserved` binaries, when declared, must exist and match SHA-256;
- project `archival_title` is checked against canonical corpus title so convenience duplication cannot silently drift;
- GitHub Actions runs this validator on relevant PR/push changes;
- `resolve` deterministically follows project → canonical source → primary file → exact crosswalk locus.

Deliberately not implemented: database/schema framework, automatic archive import, required portal IDs/URLs for offline sources, or enforcement of scholarly judgements. This fulfills #11's smallest-validation criterion without replacing the existing lean TSV structures.
