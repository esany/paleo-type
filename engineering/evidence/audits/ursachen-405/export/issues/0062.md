# Issue #62: Deferred trigger: non-archival historical/documentary Source contract

## Text

## Status
**Deferred trigger issue. No current implementation or Source-registry generalization is authorized.**

The present Corpus contains seven archival/documentary Source nodes, all of which can truthfully carry the current archival provenance fields. There is therefore no current need to redesign `corpus/sources.tsv` merely for hypothetical future Source types.

## Latent constraint
The current Source Contract requires `archive`, `fonds` and `signature` to be non-empty for every canonical Source.

That is acceptable for the current archival corpus, but it could become false if a **real non-archival historical/documentary Source object** later needs stable canonical Source identity.

The correct response is trigger-based conditionalization when the case actually occurs, not a pre-emptive universal Source ontology.

## Trigger
Admit implementation only when all of the following are true:
1. a concrete non-archival historical/documentary object is actually needed as a canonical `corpus/sources.tsv` Source node;
2. stable Source identity is required for provenance/citation/relation/reuse rather than merely for a one-off research note;
3. requiring `archive/fonds/signature` would force false or fabricated metadata;
4. existing project research/evidence records are insufficient as the truthful owner.

Until then this Issue remains deferred/unmilestoned.

## Smallest future action after trigger
If triggered, evaluate the actual Source and relax/conditionalize only the universal fields that demonstrably do not apply.

Requirements for that future evaluation:
- preserve `source_id`, descriptive source type and title/identity at the minimum level the real Source supports;
- preserve strong archival provenance requirements for archival Sources where applicable;
- never invent archive/fonds/signature values to satisfy a schema;
- keep exact inspected files/instantiations in the existing file-provenance layer when actually used;
- keep evidence class/inspection status explicit;
- avoid creating a type ontology or technology migration unless the real Source requires it.

The exact future minimal required-field set is **not** fixed by this planning Issue; it should be derived from the first real triggered case.

## What this Issue does NOT canonicalize
The following are **not automatically `corpus/sources.tsv` objects** merely because they may inform research:
- scholarly editions;
- dictionaries/lexica;
- modern research literature;
- general reference works.

Their inspected use is already governed by `methodology/evidence-policy.md` and project research audit. If repeated bibliographic maintenance or publication requires structured bibliography, #13 remains the dedicated trigger.

A future concrete case may justify canonical Source identity for a particular object, but that decision must come from its actual provenance/reuse need, not from category membership alone.

## Current routing if triggered
The former dependency references to #58, #59 and #64 are historical; those Issues are closed and are **not** live prerequisites/controllers.

If the trigger fires:
- establish the concrete non-archival Source case and demonstrated false-metadata pressure;
- derive the smallest truthful Contract change from that case;
- route any material shared CORPUS/Contract change through the canonical D-016 owner `methodology/maintenance.md`;
- use the current Project→Source use model if a project-relative use actually arises;
- keep #13 separate and activate it only if the distinct bibliography trigger also fires.

## Trigger acceptance criteria
Only after the trigger fires should a later plan demonstrate:
- [ ] the real object cannot be represented truthfully under the current universal archival non-empty rule;
- [ ] canonical Source identity is actually needed;
- [ ] the smallest conditional rule is identified from the real case;
- [ ] existing archival Source provenance is not weakened;
- [ ] no bibliographic/reference ontology is introduced without its own demonstrated trigger;
- [ ] no invented archival metadata is required.

## Non-goals
- no current Contract change;
- no bibliography manager;
- no universal taxonomy of Source types;
- no automatic migration of literature/dictionaries/editions into the Corpus;
- no RDF/RiC/TEI architecture;
- no synthetic future fixture solely to justify implementation.
