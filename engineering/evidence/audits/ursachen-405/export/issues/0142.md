## Post-#145 execution contract

This issue no longer authorizes building a second evidence-packet compiler. PR #144 introduced `tools/regii5_evidence_packet.py`; corrective #145 / PR #146 established the neutral Reg. Ii 5-only default. #142 now owns **measurement and integration of that existing derived packet**, not a competing context system.

The experimental question is:

> Is the existing packet materially smaller than the current repo-heavy working context while preserving every fact needed for correct provenance, routing, authority, uncertainty and source return?

The phase-2 objective is:

`smallest sufficient current state + maximally useful search breadth + unchanged evidence authority`

Candidate-selection state must remain explicit:

`available generator ≠ activated generator ≠ candidate returned ≠ candidate adjudicated ≠ reading promoted`

## Purpose

Measure and refine the existing deterministic **evidence-packet path** so one bounded manuscript problem can be worked without repeatedly transporting large STATUS/method/history payloads or rebuilding deterministic setup by hand.

This remains a derived research-support layer. It must not become a canonical truth store, infer scholarly state, select external witnesses implicitly, or decide readings.

## Current baseline

After #145 the default packet is deliberately neutral:

- `blind`: Reg. Ii 5 target/source/file/crosswalk addressing only; no current reading and no candidates;
- `explore`: requires a frozen caller-supplied source-only observation, then exposes only the compact current Reg. Ii 5 TSV row;
- `candidate_sources = []` and candidate policy is `NONE_ACTIVATED`;
- `adjudicate`: requires target return and cannot decide or persist a reading;
- no wholesale `STATUS.md` / `project_context.py` import;
- no automatic Reg. Ii 4 / G4 exposure.

This baseline is the object to benchmark, not something to replace before measurement.

## Measurement questions

For one or more bounded Reg. Ii 5 fixtures, measure at least:

1. serialized/input size of the current repo-heavy restart/context path relevant to the task;
2. serialized/input size of the evidence packet for the same task;
3. which provenance/routing/authority/uncertainty facts are preserved;
4. whether any omitted context causes incorrect routing, authority assignment or loss of necessary uncertainty;
5. whether the packet imports volatile STATUS history or other unrelated owner text;
6. whether source/candidate activation remains explicit rather than inferred from availability.

Do not assume a target token-saving percentage in advance. Record bytes/characters and, where a tokenizer is available without adding a dependency, token counts as a secondary measure.

## Minimal packet contract

For a bounded target, the existing packet may expose only information justified by the active phase, for example:

### Source / target provenance
- Project / Source / File identity;
- File digest;
- archival folio and digital image/PDF mapping;
- explicit statement that `VISION-INSPECTABLE` is **not** established by the compiler.

### Blind observation
- caller-supplied source-only observation;
- frozen verbatim plus digest before candidate-bearing context.

### Current reading
- compact current folio-local TSV row after the blind boundary;
- no long `evidence_note` mini-audit by default.

### Candidate interface
- generator availability and activation must be separate;
- no generator is activated by default after #145;
- later generator outputs must retain provenance and zero diplomatic evidence authority until target adjudication.

### Adjudication boundary
- target reinspection required;
- compiler cannot promote, downgrade, retain or persist a reading by itself.

## Reg. Ii 4 / external witness boundary

Reg. Ii 4 / G4 is **not part of the default packet and not part of the first #142 benchmark**. An external witness may enter a future exploration only through a separately admitted, explicit candidate-selection action. Mere existence of a G4 mapping is not activation authority.
