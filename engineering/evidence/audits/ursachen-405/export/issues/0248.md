## Problem / Gap
`DECISIONS.md` explicitly says it is a lean cross-project decision record and intentionally not a full ADR system. The bugwave contains many architecture-significant accepted and proposed choices whose context, alternatives, consequences, reversibility and supersession are otherwise distributed through dated audits/designs.

## Findings covered
F06, F12, F18, F24, F25, F30, F32, F33 plus new finding F36: architecture-decision rationale is not exposed through a systematic ADR lifecycle/index.

## Required effect
Design the relationship among:
- existing accepted `D-*` decisions;
- retrospective ADRs for already-authorized architectural choices where useful;
- proposed/rejected/deferred/superseded ADRs for current bugwave choices;
- Current Configuration (which ADRs must not duplicate);
- bounded Issues and evidence.

Use the fresh Portfolio ADR implementation only as comparator evidence: Accepted/Proposed/Superseded/Deprecated/Rejected, retrospective ADRs explicitly marked, decisions not silently rewritten, and ADRs distinct from Requirements/Issues/Programme/history.

## Next activity / readiness
**READY TO DESIGN / DOCUMENT ADR INVENTORY. NOT READY TO PROMOTE PROPOSED ADRS AS ACCEPTED.**

## Dependencies
Current `DECISIONS.md`; #245 finding trace; #246 currentness/identity semantics. D-016 applies to material architecture acceptance/implementation.

## Acceptance / close condition
- complete bugwave ADR inventory with authority-correct status;
- explicit mapping to existing D-* decisions where they already own the accepted rule;
- proposed ADRs contain context, drivers, alternatives, consequences, risk/reversibility and links to findings/requirements/issues;
- no duplicated Current State or second decision authority;
- supersession is explicit;
- decision index is understandable to a fresh developer.

## Non-goals
Do not retroactively claim Human acceptance; do not create one ADR per finding/Issue; do not make ADRs executable state; do not implement architecture.

## Whole-system return
Report which architectural choices are already governing, which remain Human-decision candidates, and what implementation remains blocked on those decisions.
