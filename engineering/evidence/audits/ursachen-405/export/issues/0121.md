## Purpose / owner admission

Implements the bounded generic safeguard explicitly requested and admitted by the Human Owner on 2026-09-08 and documented in #120: preserve semantic boundaries between scholarly disciplines, technical/functional contracts and ordinary human language so that terminology itself cannot become a hidden source of claim inflation or a chat-only convention.

## Demonstrated failure class

Repeated real cases showed that lexical identity is not semantic identity:

- `G2 PASS` can be misreported as “transcription finished” although it may mean representation completeness with unresolved readings;
- technical/CI `PASS` can be mistaken for scholarly validation;
- `complete`, `resolved`, `status`, `role`, `source`, `owner`, `witness`, `event`, `evidence`, `identity` and `validation` have different meanings across archival/diplomatic/palaeographic/editorial/historical, GitHub/API/CI and ordinary-language contexts;
- observable script-feature difference, hand hypothesis and scribe identification are distinct claims despite everyday linguistic proximity.

## Changes

### `AGENTS.md`
Adds one universal semantic-context/translation guardrail:
- meaning comes from the owning domain/contract, not the word alone;
- no automatic equivalence across scholarly domains, technical contexts or ordinary language;
- German↔English, technical↔scholarly and domain↔domain translation preserves claim type, target/scope, evidence/authority level and uncertainty;
- qualify consequential polysemy rather than inventing a global definition;
- no forced mapping when meaning cannot be preserved losslessly.

### `methodology/workflow.md`
Adds the executable semantic-boundary check for consequential handoffs/translations:
`source semantic owner + source claim → target consumer/contract → loss/gain/ambiguity check`.

It explicitly governs Domain→Dev, Dev→Domain, machine→human, human→structured-value and language translation. Technical results must return to the domain as the exact property tested, not as upgraded scholarly acceptance.

### `requirements/domain-requirements.tsv`
Adds `REQ-GWP-011`: consequential cross-domain/technical/human terminology and translations must preserve owning meaning, scope, evidence/authority and uncertainty. Deterministic checks are allowed only for stable formally owned vocabularies.

### `DECISIONS.md`
Adds D-019 as the durable cross-project rationale so a fresh context does not need this chat to understand why lexical equality is not a mapping rule.

### Regression
`tests/test_governance_ownership.py` now protects only the durable owner chain (`AGENTS.md` → workflow → D-019 → `REQ-GWP-011`). It deliberately does **not** attempt to validate open scholarly meanings or grow into a lexical-governance checker.

## Explicit examples protected

```text
technical / CI PASS                 ≠ scholarly validation
G2 PASS                             ≠ every reading resolved / transcription “finished”
Project research_function principal ≠ historical principal actor/role
canonical Source node               ≠ any generic citation/information source
textual witness                     ≠ historical/legal witness
same wording                        ≠ same identity / date / hand / production stage
```

## Non-goals

- no global glossary or translation registry;
- no universal ontology;
- no controlled vocabulary for every discipline;
- no automatic meaning inference from strings;
- no new agent/role architecture;
- no Project/CORPUS/transcription/gate-state change;
- no requirement to type or annotate ordinary low-consequence conversation.

## Restartability / anti-chat-monopoly

The durable rule is reconstructable from canonical repository owners (`AGENTS.md`, `workflow.md`, `REQ-GWP-011`, D-019). Issue #120 remains the audit/admission trail; this PR is implementation history, not a separate truth store.

Closes #120.
