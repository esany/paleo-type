This is an additive case extension, not a replacement of the existing folio-centred crosswalk model.

### Existing case preserved
- existing `crosswalk.tsv` rows remain valid and unchanged;
- archival folio remains required for the folio-centred table;
- Reg.-Ii. crosswalk semantics and fixtures are not migrated.

### New real case
- add `digital-crosswalk.tsv` for exact provider-image File ↔ exact PDF File/page mappings when archival foliation is not yet established;
- validate File existence, same-Source provenance, mapping IDs, mapping status and positive PDF page numbers;
- expose digital mappings in `source_contract.py resolve` and Project context;
- add the exact Human-supplied Nr. 632 compact PDF as a separate File and Project-use evidence;
- persist 135 observed mappings from provider JPEG Files `0001`–`0135` to compact-PDF pages 1–135.

### Claim ceiling
The digital mapping does not assert archival foliation, document/material-object boundaries, internal Source identity or equivalence with any other compact/full PDF byte sequence.

### Regression coverage
- folio-free digital mapping accepted;
- cross-Source File mapping rejected;
- invalid PDF page rejected;
- Nr. 632 restart context exposes exact PDF File and digital crosswalk;
- resolver returns all 135 mappings;
- existing source-contract / Reg.-Ii. tests remain the preservation fixtures.
