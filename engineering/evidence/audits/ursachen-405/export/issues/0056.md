# PR #56: Generalize source containment to part_of

- Labels: –

## Text

Replace the type-specific `archival-acts.tsv` / `archival_act_id` model with one generic source-node register plus evidence-status-controlled `part_of` relations.

Key invariants:
- every historical/documentary object needing stable identity is a row in `corpus/sources.tsv`;
- `source_type` is descriptive, not a schema switch;
- containment is `subject part_of object` in `corpus/relationships.tsv`;
- both endpoints must resolve to source nodes;
- `part_of` cycles are rejected;
- arbitrary depth and multiple evidenced parent paths are supported;
- project roles/files/crosswalks stay attached to the source node actually used;
- resolver returns all `part_of` ancestry paths instead of assuming `parent_archival_act`;
- no database, ontology, or new hierarchy table.

The current Knau data remains four distinct protocol source nodes related to three larger act source nodes. Stable URNs remain evidence-only and are never synthesized.
