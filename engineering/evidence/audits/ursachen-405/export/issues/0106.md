## Text

## Purpose
Operationalize an already-established restartability/canonical-ownership requirement after repeated Reg. Ii 4 execution-context failures produced persistable transcription work in transient tool storage before GitHub persistence.

## Existing requirements operationalized
- REQ-GWP-001 — one canonical owner per durable fact/state
- REQ-GWP-008 — research state restartable without old chat
- REQ-RSE-003 — canonical truth distinct from transient/derived surfaces
- REQ-AI-007 — consequence-based write boundaries

No new requirement family or research-data model is introduced.

## Changes
- `AGENTS.md`: adds a binding repository-first research-persistence guardrail. Persistable/restart-relevant research artifacts must be written directly to their repository owner or working branch when an authorized write path is available; chat/tool sandboxes are not fallback research-state stores.
- `methodology/workflow.md`: distinguishes permissible ephemeral evidence processing (staged bytes, renders, crops, temporary calculations) from persistable research state and defines direct branch writes plus the technical-blocker behavior.

## Boundaries
- does not require source binaries to be stored in Git;
- does not prohibit temporary image/PDF derivatives needed for visual inspection;
- does not require every exploratory thought to be committed;
- does not change Project, corpus, transcription, gate or scholarly state;
- no new artifact registry, workflow engine, agent system or enforcement platform.

## Regression fixtures
- Reg. Ii 4 fol. 307r: analysis reached persistable state before the intended GitHub write and execution ended before persistence.
- Reg. Ii 4 images 669–672: four prepared local TSV representations were reported before branch writes, again exposing dependence on the originating execution context.

The Human Owner explicitly requested this repository-first rule after reviewing the gap, satisfying the material-change admission boundary for this bounded process clarification.
