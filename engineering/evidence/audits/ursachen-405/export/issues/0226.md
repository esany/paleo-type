## Problem / hypothesis to test

The repeated system failure pattern is broader than one phase or one Project:

```text
higher-level authorized outcome
→ decomposition into local task / repair / review / implementation slice
→ local PASS / STOP / closure
→ higher-level outcome continuity is weakened, lost or falsely treated as complete
```

The #225 self-audit currently counters this locally through child-Issue admission, parent/child reconciliation, Local-PASS containment, repair-return and vertical-value tests.

The candidate generic abstraction is:

> **Outcome-Continuity under Decomposition:** whenever an authorized higher-level outcome is decomposed, interrupted or locally repaired, the local result must remain bounded to its actual authority, be reconciled to the higher-level outcome, and return to that outcome cursor when it remains valid. Local completion must not imply whole-outcome completion unless the parent acceptance criteria are independently satisfied.

This should be assessed independently of particular phases such as Analysis, Requirements, Concept, Development or scholarly execution.

## Review questions

1. Is this invariant already fully covered, without material semantic gaps, by existing owners such as `methodology/maintenance.md`, `methodology/workflow.md`, `methodology/quality-and-learning.md` and current programme-transition semantics?
2. If only partially covered, what exact cross-phase/cross-context semantics are missing?
3. Does the missing capability genuinely generalize across research Projects, system-development work, bounded support/repair and review contexts?
4. Can the invariant be represented or enforced deterministically without creating a second truth store or a monolithic workflow engine?
5. Which parts must remain contextual/AI-assisted or Human/specialist judgement?
6. What is the smallest canonical owner/mechanism if promotion is warranted?
7. What would falsify the need for a new generic mechanism?

## Candidate invariant shape to evaluate

```text
DECOMPOSE
parent outcome → bounded local work

CONTAIN
local result has only local authority

RECONCILE
local result → explicit consequence for parent outcome

RESUME
if parent remains valid → return to parent cursor

TERMINATE
only parent-level acceptance or a real authority/evidence/feasibility invalidation may end the parent outcome
```

This is a review hypothesis, not an admitted state model.

## Acceptance / disposition

Return one of:

- **ALREADY COVERED** — existing owners fully provide the semantics; no new generic rule/mechanism needed. Identify the owner and any discoverability/test gap only.
- **REFINE EXISTING OWNER** — a bounded generic semantic gap exists and can be closed by the smallest refinement of an existing owner.
- **GENERIC EXECUTABLE INVARIANT WARRANTED** — stable semantics justify a reusable deterministic/derived mechanism; prepare requirements/concept and enter D-016 before material implementation.
- **CONTEXTUAL ONLY** — the apparent invariant cannot be safely generalized/formalized; retain it as contextual review practice.
- **DEFER / INSUFFICIENT EVIDENCE** — more cross-fixture evidence is needed.

## Falsification / anti-bloat criteria

FAIL any promotion proposal if it:

- merely restates existing maintenance/workflow prose without closing a demonstrated semantic or execution gap;
- creates a duplicate parent/outcome truth store;
- requires every task to enter a universal hierarchy/state machine;
- uses GitHub parent/child structure as canonical research authority;
- hard-codes #225 or Reg. Ii 5 semantics;
- adds ceremony without preventing a demonstrated loss-of-outcome failure;
- leaves the critical reconciliation/return decision dependent on model memory even though the semantics are stable enough to derive mechanically.
