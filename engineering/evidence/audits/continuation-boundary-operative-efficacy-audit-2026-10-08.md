## 2. Reproduction

Observed failure:

```text
already-authorized coherent work block
→ one bounded action is completed or reported
→ assistant emits a final answer as if the block were finished
→ remaining authorized work is left as a suggested “next step”
→ Human must send a new command (“weiter”, “ausführen”, or equivalent)
→ only then does the assistant continue work that needed no new Human-Owner decision
```

The defect is not that a bounded step can have a legitimate result. The defect is that the execution context treats its own response boundary as a Human-approval boundary. The Human is thereby made into a relay for continuation that the existing authority already permits.

This is the same natural failure family as #297:

- a coherent higher-order outcome is reduced to an immediately convenient fragment;
- local completion is allowed to stand in for continuation of the authorized block;
- the residual is surfaced as a new prompt instead of being executed;
- Human burden and false-Lean risk increase even though no new owner decision is needed.

## 3. Platform boundary — precise qualification

ChatGPT cannot initiate a new user-visible turn after it has returned a final answer without a new user message. That is a platform boundary. This record does not claim autonomous new turns, background execution, a workflow engine or a persistent job runner.

The platform fact does **not** justify voluntarily ending the current turn while the authorized work can still be performed through further tool calls in that same turn. It also does not convert a routine continuation into a Human-Owner decision.

Correct distinction:

| Situation | Required behavior |
|---|---|
| More authorized work remains and is executable in the current turn | Continue it in the current turn; do not ask for a follow-up prompt. |
| A real owner-reserved decision is missing | Return exactly that bounded authority question. |
| Required evidence is unavailable or the claim ceiling is reached | Return the action-local evidence limitation and preserve the valid cursor. |
| A required tool/capability genuinely cannot perform the action | Return a truthful, scoped tool boundary and the valid continuation state. |
| The current platform turn must end despite unfinished authorized work | State the platform ceiling honestly; do not present it as Human approval or invent completion. Persist/refer to the restartable state where authorized. |
| No authorized continuation remains because the block reached its terminal condition | Close with the actual research/system result, evidence ceiling or authorized escalation. |

The central requirement is therefore bounded to one active authorized turn/work block:

> Within an active authorized turn/work block, the agent must execute the complete coherent block that remains derivable and authorized. It must not manufacture a new Human command, confirmation or routing task merely because one response has been produced. Only a real owner, evidence, capability or explicitly unavoidable platform boundary may end the active execution path; none of these may be mislabeled as completion.

## 4. Required behavior

Before producing a final answer, the active context must re-check:

1. What complete owner-authorized outcome is this turn serving?
2. Is the current response only a progress report while executable work remains?
3. Are remaining actions already authorized, derivable and within the same coherent block?
4. Is any proposed “next step” actually a new owner decision, new evidence requirement, new material scope or new top-level mutation?
5. If not, continue internally and do not ask the Human to say “continue”.
6. If a boundary is real, name the exact boundary, affected action, current evidence and valid restart/return condition.

This is an execution/acceptance rule, not permission to run indefinitely. Apply the existing progress/delta rule and terminal semantics; do not create an autonomous search loop.

## 5. Copy-ready internal execution / continuation prompt

The following is an internal steering rule for the active ChatGPT context. It does not claim that ChatGPT can create new turns autonomously:

```text
CONTINUATION RULE — ACTIVE AUTHORIZED TURN / COHERENT WORK BLOCK

Treat the current user-authorized task as an active execution block, not as a sequence of independent mini-prompts.

After each tool result or progress message:
1. Re-resolve the complete owner-authorized outcome and the current coherent block.
2. Continue all remaining work that is already authorized, derivable and executable in this same turn.
3. Do not stop merely because one bounded step, local check or intermediate report is complete.
4. Do not ask the Human for “weiter”, “ausführen”, confirmation or a new command when the next action is already authorized and no new owner/evidence/capability boundary exists.
5. Do not replace the coherent block with the smallest convenient fragment. Preserve coupled canonical, evidence, provenance, restartability, acceptance and return obligations.
6. Do not claim whole-outcome completion from a local PASS, one commit, one issue update, one test run or one intermediate result.
7. Before finalizing, classify the remaining state:
   - continue now: authorized work remains in the active turn;
   - owner return: a genuinely non-derivable Human-Owner decision is required;
   - evidence return: the required evidence is unavailable or the claim ceiling is reached;
   - tool/capability return: the required action cannot be performed by the available capability;
   - platform ceiling: the current turn must end although authorized work remains.
8. Use owner/evidence/tool/platform return only for the exact boundary. Never disguise a routine continuation as a Human decision, and never describe a platform ceiling as completion.
9. When a real boundary ends the active turn, preserve the restartable cursor: completed work, remaining authorized work, exact boundary, evidence state, claim ceiling, affected owner and valid next continuation. Do not invent a new priority or scope.
10. ChatGPT cannot initiate a new user-visible turn by itself. This rule governs continuation within the current turn and truthful handling of an unavoidable platform end; it does not promise background or autonomous future turns.

Terminal output must be one of:
- the complete coherent authorized result;
- a bounded scholarly/system evidence ceiling;
- an authorized owner/escalation return;
- a truthful action-local tool/evidence/platform boundary with restartable state.
```
