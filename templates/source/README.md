# New source — lean intake

Use the existing canonical owners; do not create a source-specific metadata silo.

1. Add every evidenced historical/documentary object that needs stable identity once to `corpus/sources.tsv`. Use a stable `source_id` and a descriptive `source_type`; do not create a new table merely because the object is an act, protocol, section, attachment or other level. Record `boundary_status` and `boundary_basis` explicitly. A filename, upload label, Project path or convenient export range is not sufficient boundary evidence by itself. If the Source extent is only partial or unresolved, preserve that state instead of guessing a complete boundary; unresolved Source extent blocks only claims that require that boundary/locus.
2. Express evidenced containment in `corpus/relationships.tsv` as `part_of` from part to whole. Add intermediate source nodes only when they matter for identity, provenance, citation or research. Do not invent hierarchy for symmetry.
3. If a digital file is actually used, add it to `corpus/files.tsv` with exact filename, SHA-256, coverage, rights and preservation state, linked to the source node the file materially instantiates. If SHA-256 matches an existing canonical File, reuse that File identity and record any consequential supplied filename difference as provenance rather than creating a duplicate File. Do not place protected bytes in the public repository without authority.
4. When consequential work depends on page/image/locus mapping, create `corpus/source-data/<source_id>/crosswalk.tsv` from `crosswalk.tsv` in this directory. Preserve folio, export/image ID, PDF page and stable image URN as separate identifiers. Every row requires an explicit `mapping_status` and non-empty `evidence` basis, including `unresolved`/`working` rows. Never invent missing identifiers or URNs. Do not force adjacent material outside an evidenced source boundary into its crosswalk.
5. Make the Project routing decision only after Corpus Source/File intake. `CORPUS_ONLY / NO_PROJECT_YET` is valid. If a human-established research purpose selects or creates a durable Project, set its `project_source_id` to the documentary anchor required for structural resolution and record actual Project-relative research functions/loci in that Project's `source-uses.tsv`. Source structure or File availability must not create a Project or choose its research priority.
6. If inherited transcription/apparatus/palaeographic material cannot be attributed safely to one exact Source/File/locus, do not promote it by path, siglum, filename or textual similarity. Create project-local `research/legacy-witness-provenance.tsv` from the template only when such uncertainty exists; preserve allowed recovery/checking uses and the explicit promotion rule. Unresolved witness provenance blocks witness-specific scientific promotion, not recovery, checking or methodology tests.
7. Run `python tools/source_contract.py validate` and the deterministic test suite. `tests/test_source_critical_acceptance.py` enforces the recurring Source-boundary, crosswalk-evidence and legacy-provenance safety invariants.
8. Resolve the canonical chain for a selected Project with `python tools/source_contract.py resolve --project <project> --source-id <source_id> [--locus <folio>]`. The resolver follows generic `part_of` ancestry and reports whether the source is the project root, internal or external.

The machine contract is `corpus/source-contract.json`; the deterministic regression suite adds failure-derived acceptance guards that are unsafe to express as schema alone. Software validates explicit structure/evidence state but does not adjudicate Source interpretation, witness dependency or manuscript truth.
