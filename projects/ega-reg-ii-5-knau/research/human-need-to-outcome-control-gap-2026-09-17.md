# Human-need → scholarly-outcome control gap — Reg. Ii 5 pilot learning (2026-09-17)

Status: **Project-local learning / demonstrated failure pattern. Not generic METHOD, not a Project-priority decision, not a new scholarly scope, and not implementation admission.**

## Human-Owner need in this pilot

The Human Owner is not expected to supply palaeographic, philological, editorial, archival or software-engineering expertise. The practical need driving this pilot is reliable scholarly support for manuscript work, including obtaining a scientifically usable diplomatic representation of a small bounded manuscript locus without having to design the expert method or technical system personally.

For the current Reg. Ii 5 fixture, substantial work has concentrated on fol. 61v–63r. The repository now records G2–G4 maturity for that evaluated locus while G5/G6 are not reached. The owner experience is that, after more than two weeks of work, process/support/governance correction repeatedly displaced the still-unmet usable-output need.

This file does **not** redefine the Project purpose or authorize G5/G6 work by itself. It records a quality/control failure exposed by the pilot.

## Observed failure pattern

Several individual safeguards are correct and necessary:

- no Project/scope/priority invention by AI;
- evidence before plausibility;
- explicit uncertainty;
- support/resource state does not create task authority;
- `active_scope = unset` and `NEXT ACTION = NONE` are valid states;
- technical PASS does not imply scholarly adequacy;
- pilot-specific findings do not automatically become generic METHOD.

However, correct local safeguards can still compose into an unsatisfactory system behaviour when the **stable Human need / intended scholarly outcome ceases to function as a quality discriminator for execution**.

In the observed pilot sequence, the system repeatedly became better at refusing invalid transitions, repairing state, documenting support failures and preserving authority boundaries, while the Human Owner still lacked the desired usable diplomatic result for the small manuscript locus.

The resulting failure is not that the safeguards are wrong. The failure is that the system can become locally correct while globally under-serving the authorized research purpose and user need.

## Distinction from L026–L029

This finding complements but is not identical to existing lessons:

- L026: Project-purpose recoverability during broad direction formation;
- L027: pilot material must not define generic system purpose;
- L028: support dominance as a secondary symptom of weak recovery;
- L029: scientific capability must be evaluated separately from reliability/auditability/overhead.

The additional issue here is **control continuity from Human need to scholarly outcome**:

> A system that knows what it must not do still needs a reliable way to determine whether its bounded actions are converging on the Human Owner's intended scholarly outcome, without requiring the non-specialist owner to substitute for domain or engineering expertise.

## Quality implication for the current pilot

The Human Owner should not be required to know that a desired usable diplomatic result corresponds to a particular gate transition, specialist competence mix, validation action or software mechanism.

Given an owner-authorized outcome and bounded source scope, the system should be able to expose:

1. current maturity/evidence state;
2. unmet requirements for the desired outcome;
3. which next work is deterministically implied by those requirements and current state;
4. which parts require AI scholarly reasoning;
5. which parts require qualified specialist validation;
6. which genuinely non-derivable decisions still require the Human Owner.

Owner authority remains intact: the system must not manufacture a new scope or research priority. But it should also not convert every domain or process choice into an Owner question merely because the implementation has not yet operationalized the derivation.

## Lean / State-of-the-Art expectation

The quality target is not maximal process. It is the **minimum adequate mechanism that achieves maximal appropriate scholarly and engineering quality for the concrete need**.

That means:

- use current disciplinary best practice where consequential;
- activate only the competencies required by the source/problem;
- preserve uncertainty and evidence boundaries;
- use deterministic software for stable identities, state, provenance, admissible transitions, derived context, regressions and validation wherever semantics are stable enough;
- use AI for genuinely non-deterministic interpretation, synthesis, hypothesis generation and explanation;
- keep qualified specialist judgement explicit where AI/method compliance cannot establish adequacy;
- avoid hand-maintained duplicate truth and avoid asking the Human Owner to act as substitute specialist, repository operator or software architect;
- stop adding mechanism when the demonstrated requirement is satisfied and return to scholarship.

## Current disposition

Project-local demonstrated learning: **accepted as a real pilot problem frame.**

No generic METHOD change follows from this file alone. No new `NEXT ACTION` is created. No G5/G6 authorization is created.

The generic relevance should be tested against later/different manuscript projects. If the same failure recurs — owner-authorized scholarly outcomes repeatedly fail to drive execution because local guardrails/gates/support states do not compose into an outcome-oriented control path — then Generic-Fit is strengthened and a smallest cross-project safeguard may be warranted.
